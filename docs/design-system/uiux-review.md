# 뭉실 전체 UI/UX 점검 기록

최종 갱신일: 2026-09-28
기준 문서: `docs/design-system/cloud-comfort-product.md`
검증 화면: 360×800, 390×844, 430×932 모바일, 600×800 중간 폭, 1280×600 데스크톱 중앙 프레임, 360×400 축소 높이

## 1. 이번 점검 범위

공개 랜딩과 인증 화면, 5개 핵심 탭, TODO 가져오기, 챌린지·대화방·1:1 대화·게시물·사용자 상세, 알림·설정·약관, 운영자 화면까지 현재 존재하는 28개 `page.tsx` 라우트를 검토했다.

- `/`, `/start`, `/forgot-password`, `/reset-password`, `/verify-email`
- `/onboarding`, `/today`, `/explore`, `/todos`, `/todos/import`
- `/challenges`, `/challenges/[id]`, `/challenges/[id]/chat`, `/me`, `/notifications`, `/settings`
- `/posts/[id]`, `/people/[handle]`, `/people/[handle]/connections`
- `/messages`, `/messages/[id]`
- `/privacy`, `/terms`, `/admin/reports`

브라우저 점검에서는 세 모바일 폭 모두에서 문서 전체의 가로 넘침이 없었고, 제품 화면의 세로 스크롤은 `.app-scroll` 하나로 유지됐다. 시트는 별도 포털 레이어와 `.sheet-body` 내부 스크롤을 사용한다.

## 2. 이번에 확인하고 수정한 공통 결함

### TODO 가져오기 스크롤

- 원인: 하단 저장 CTA가 `position:absolute`여서 폼 높이에 포함되지 않았고 화면 높이에 따라 마지막 입력을 덮거나 스크롤 범위가 부족해졌다.
- 수정: 폼을 세로 flex 흐름으로 바꾸고 CTA를 문서 흐름에 포함된 `position:sticky`로 전환했다.
- 기준: 짧은 루틴 가져오기는 CTA가 화면 하단에 머물고, 긴 단일 TODO 가져오기는 모든 카테고리·반복 항목 뒤까지 자연스럽게 스크롤돼야 한다.

### 루틴 가져오기 반복

- 단일 TODO뿐 아니라 루틴에도 반복 정책을 노출했다.
- 루틴은 `원본 유지 · 반복 없이 · 항목별 설정`을 제공하고, 항목별 설정에서는 각 TODO의 이름·날짜·시간·반복을 조정한다.
- 서버는 원본 항목이 아닌 ID를 거부하고, 선택한 정책대로 반복 시리즈 또는 단일 TODO를 생성한다.

### 스레드형 TODO 그룹

- 오늘과 TODO 화면에 기존 루틴 묶음을 접을 수 있는 그룹으로 표시한다.
- 접힌 그룹에서도 완료율과 다음 TODO를 보여주며, 펼치면 실행 순서를 세로 연결선으로 표현한다.
- 반복 일정은 `seriesId`로 같은 그룹에 이어지고 한 TODO 또는 반복 시리즈가 여러 그룹에 중복되지 않도록 생성·편집 단계에서 막는다.
- TODO 작성·편집 시 `그룹 없음`과 기존 루틴을 전용 선택 카드로 제공하고, 편집에서는 현재 그룹을 미리 선택한다. 반복 TODO의 그룹 변경은 시리즈 전체에 반영한다.

### Bottom Sheet

- 앱 셸 내부 transform과 overflow로 시트가 잘리던 문제를 `document.body` 포털로 해결했다.
- 시트 헤더와 닫기는 고정하고 본문만 스크롤한다.
- 앱 배경은 `inert`, 배경과 앱 스크롤은 잠그며 닫은 뒤 원래 포커스를 복구한다.
- 스크롤바와 입력 사이에 여백을 두고 뭉실 색상의 얇은 스크롤바를 사용한다.

### 브라우저 기본 UI

- TODO 작성·편집·가져오기의 날짜, 시간, 카테고리, 반복을 공통 전용 UI로 교체했다.
- 게시 공개 범위는 `전체 공개 · 팔로워 · 나만 보기` 전용 선택 카드로 교체했다.
- `게시`와 외부 `공유` 용어를 분리했다.

### 터치 영역

- 브랜드 링크, 인증 전환 버튼, 약관 돌아가기 링크를 최소 44px 높이로 보강했다.
- 360px TODO 주간 달력은 카드 폭을 안전하게 확장해 날짜 버튼의 터치 폭을 확보했다.

### 2026-09-06 P1 안정화

- 중첩 `Sheet`는 전역 레이어 스택에서 최상위만 Esc와 포커스 트랩을 처리하고, 마지막 시트가 닫힐 때만 앱 `inert`와 스크롤 잠금을 복원한다. 메시지 삭제 전환과 사진 검수 중 신고 흐름을 실제 브라우저에서 확인했다.
- 앱 프레임은 600px 폭에서도 최대 430px을 유지하고, 1280×600에서는 사용 가능한 높이 안에 들어가 하단 탭이 잘리지 않는다.
- TODO 그룹·카테고리 조회의 `아직 모름/오류/없음`을 분리해 제목만 저장할 때 기존 관계 필드를 보내지 않는다.
- 루틴 가져오기 항목 초안은 반복 모드 왕복에도 보존되며 명시적인 `원본으로 초기화`만 원본을 복구한다.
- 게시와 챌린지 인증 사진은 미리보기·제거·진행·재시도를 제공하고, 업로드가 성공한 뒤 API가 실패하면 같은 미디어 ID를 재사용한다.
- 반복 종료와 작성 중 이탈은 범위와 손실 내용을 설명하는 전용 확인 시트를 거친다.
- 채팅 신규 수는 소켓 이벤트 횟수가 아니라 실제 렌더된 마지막 메시지 변화로 계산하고, 읽음 완료는 `chat-inbox`와 앱 셸 배지 캐시를 함께 갱신한다.
- 상세 구현·검증 상태와 외부 의존성은 `docs/reviews/2026-09-06-frontend-uiux-remediation-progress.md`에서 UX ID별로 관리한다.

### 2026-09-06 탐색·대비·챌린지 상태 보완

- 해시태그는 피드·인기 태그·검색 결과 어디서 진입해도 통합 결과에서 관련 게시물을 바로 보여준다. 기존 `type=tags` 직접 URL도 보존해 같은 동작으로 해석한다.
- 검색 결과 종류는 `tab` 역할을 흉내 내지 않고 표준 버튼 그룹과 `aria-pressed`를 사용한다.
- 파스텔 면의 작은 보조 글자는 전용 `--ink-on-pastel` 토큰과 13px 최소 크기를 사용한다. 해시태그 lilac 면과 완료 TODO aqua 면의 computed style을 실제 브라우저에서 확인했다.
- 마이의 그룹 명칭과 관리 링크를 현재 `/todos/routines` 화면에 맞췄다.
- 챌린지 상세는 시작 전·종료 상태에 불가능한 참여·인증·종료 행동을 내놓지 않고 상태 안내를 표시한다. 사진 검수는 대상별 답변 상태와 확대 시트를 제공한다.

### 2026-09-06 마이·연결 화면 사용자 피드백 반영

- `탐색`은 5개 핵심 탭의 상위 맥락이고 `검색`은 그 안의 하위 과업이다. 검색 화면의 뒤로가기 문구는 `탐색`, 보조 문구는 `실천 찾기`로 바꿔 같은 말이 제목처럼 반복되지 않게 했다.
- 챌린지 상세의 `오늘 인증하기`와 참여자 검수 보조 행동 사이에 12px 간격을 두어 두 버튼의 경계와 위계를 분명히 했다.
- 마이의 등급 카드는 `/me/rank` 상세로 이어지며 현재 등급, 다음 등급까지의 진행, 뭉실력 적립 기준, 전체 등급 경로를 보여준다.
- 나의 배지는 hover 설명과 클릭 가능한 공통 `Sheet`를 함께 제공한다. 시트에는 배지 설명, 만든 곳, 획득 조건·기록, 관련 챌린지와 상세 진입점을 표시한다.
- 팔로워·팔로잉 동적 라우트는 개발 캐시를 재생성한 뒤 두 URL 모두 200 응답과 목록 렌더를 확인했다.

- **구현됐지만 외부 통합 미검증:** 합성 PostgreSQL HTTP E2E의 핵심 순환과 1:1 대화 요청→수락→읽음→차단 흐름, MinIO 업로드, 실제 WebSocket 재접속. CI에서 실행하도록 구성했지만 이번 Windows 로컬 환경에서는 DB·스토리지 서비스를 사용하지 않았다.

- **로컬 검증 범위:** 격리 서비스 동작 테스트와 체험 모드 브라우저에서 알림 읽음·배지, 차단·해제, 검색 조건 변경 후 선택 저장을 확인했다. Playwright는 이 Windows 실행 환경의 `spawn EPERM`으로 실행되지 않았고 360/390/430px viewport, 낮은 높이, 실제 모바일 키보드 및 실패 주입 브라우저 검증은 남았다.
- PostgreSQL·MinIO·Linux 이미지·백업 복원 검증은 기존 별도 후속 항목으로 유지한다. 이번 작업은 서버 접속·배포·서버 통합 검증을 포함하지 않는다.

- 시트 캡처는 별도 창에서 배경만 캡처되는 문제를 발견해 제목 확인·프레임 대기·시스템 합성 화면 캡처로 바꿨다. 동작 통과와 올바른 이미지 확보를 별도로 판정한다. 오프라인 에뮬레이터의 사진 검사는 테스트용 로더에서 loopback만 허용하며 제품 연결 정책을 바꾸지 않는다.

### 2026-09-28 TODO·그룹·관계 후속 구현

- TODO 날짜·시간을 바꾸지 않으면 원본 ISO 일시의 초·밀리초를 보존한다. 복잡한 반복은 `원본 반복 유지`로 표시하고 원본 RRULE을 전송한다. 카테고리·그룹 조회 실패와 잘못된 응답을 빈 목록으로 처리해 기존 관계를 지우지 않는다.

- 그룹 관리의 이름·구성·완료 수·게시 진입을 웹에 맞췄다. 서버 날짜/제목 검색·추가 조회·중복 제거와 선택 목록을 분리하고 다른 그룹의 반복 시리즈는 선택하지 못하게 한다. 편집은 공개 범위를 덮어쓰지 않으며 변경 후 닫기에는 확인 시트를 제공한다.

- 직접 기기 테스트는 앱 APK와 테스트 APK를 함께 빌드한다. 테스트 APK만 빌드하면 이전 앱이 설치되어 최신 코드 검사로 오인할 수 있다. 저장 상태 복원 검사를 실제 프로세스 종료 검사로 표시하지 않는다.
- 공개 프로필은 서버의 수치·등급·관계 상태를 명시 모델로 읽고 누락을 0/false로 숨기지 않는다. 관계 조회 실패 중에는 팔로우·메시지를 막고 재조회하며, 접근 권한 상실 후에는 이전 게시 기록을 제거한다. 팔로우 목록은 별도 방향 선택·추가 조회·중복 제거와 접근할 수 없는 사용자 안내를 제공한다.

### 2026-09-28 게시·검색 후속 구현

- 게시 시트의 사진·한마디·태그 확정/삭제·공개 범위 순서와 설명을 웹에 맞췄다. 공개 범위만 바꾼 닫기도 확인하며 저장 중 조작을 제한한다. 실패한 본문과 제출 키는 공통 저장 상태로 복원한다.
- 기기 검사에서 시트 안 사진 선택 상태의 복원 누락을 발견했다. 게시 폼은 선택/촬영 URI를 시트 바깥 `PhotoDraft`로 소유하고 미완료 URI와 미디어 ID를 함께 확인해 제출을 막는다. 실제 OS 권한·스토리지 성공과 합성 선택기 검사는 구분한다.
- 검색은 웹 순서의 유형별 섹션·수치·미리보기/더보기, 최근 검색·유형/입력 복원과 명시 모델·StateFlow를 적용했다. 필수 배열·수치 누락을 빈 결과로 숨기지 않고 늦은 이전 응답을 현재 검색에 표시하지 않는다. 목록과 조건은 LazyListScope 전에 스냅샷으로 읽는다.
- 기본 게시 시트와 검색의 웹/앱 공유 캡처를 추가했다. 확보 범위와 남은 시각 차이·실기기/통합 검증은 별도 후속 기록에 남긴다. 실제 PhotoPicker의 파일 읽기·presign 실패 검사에서는 사진 제외 후 오류와 재시도 표시가 함께 정리되는지 확인했다.

### 2026-09-28 챌린지 인증·검수 후속 구현

- 인증/새 사진 재인증은 웹의 사진→한마디 순서와 문구를 사용하며, 폼 바깥 사진 URI·미디어 ID·미완료 상태와 실패한 제출 키를 함께 복원한다. 재인증은 인증 방식과 관계없이 사진을 요구한다. 저장 중 입력을 막고 실패 시 사진·한마디를 유지한다.
- 검수는 사진 확대·신고와 기준별 선택을 제공한다. 사진 로딩 오류에는 재시도를 제공하고 실제 사진을 확인하기 전에는 판정 선택과 제출을 막는다. 검수 응답의 필수 배열·수치·기준 누락을 빈 대기열로 표시하지 않는다.
- 검수 초안은 인증 ID·시도 번호·기준에 연결하며, 로딩 중 항목 없음과 새 인증의 도착을 구분한다. 이전 판정의 선택/단계·제출 키는 같은 항목의 저장 상태 복원에서 유지하고 새 시도나 변경 기준에는 적용하지 않는다.
- 시작 전·종료·잘못된 일정·참여 상태에 따라 인증과 재인증 진입을 구분한다. 상세 조회 오류 중에는 이전 권한의 편집·참여 행동을 계속 표시하지 않는다. 이는 로컬 화면 정책이며 서버의 실제 종료/멤버십 검증을 대신하지 않는다.
- 서버의 재인증/검수에 종료·기간·멤버십 검사 누락이 있어 로컬 서버와 웹 재인증 버튼 조건도 보완했다. 거부 상태에서 쓰기가 실행되지 않는 합성 행동 검사와 웹 3폭 검사를 추가했다. 서버·웹 배포와 실제 DB 경합 검사는 별도로 남는다.

- 게시 폼이 계정·대상·모드와 사진 URI/mediaId/pending·본문/키/시각을 함께 소유한다. 불확실한 전송 뒤 입력·사진·공개 변경을 잠그고 같은 요청으로 명시적 결과 확인만 제공한다. 진행 중 복원도 자동 전송하지 않는다. 5분 경과/시계 역행은 마이 게시 기록 확인을 안내한다.
- 닫기를 서버 게시/완료 취소로 처리하지 않는다. 미완료 사진·잘못된 태그는 게시를 막고 입력을 유지한다. 401/403 잠금과 게시 ID 확인·세션/취소 검사 뒤에만 성공 처리한다. 그룹 목록/시트도 계정·세션 범위로 분리한다.
- Android unit133·앱/시험 APK·lint0errors/32warnings 및 root lint/test/build 통과. Compose는 복원 시험 보강·계정 전환/닫기2개 추가 후 **컴파일만 확인**했다. 현재 화면의360/390/430dp·200%·IME·TalkBack·실제 OS 복원·사진/실제 DB 통합은 미검증이다. 기존 ANR 환경을 재실행해 통과한 것으로 처리하지 않는다.

## 2026-10-23 Android V1 M-08 · 응원·가져오기

- [설계](../redesign/android-v1/social-and-import-spec.md)·[현재 검사](../redesign/android-v1/implementation-m08.md). 기존5탭·피드의 나도 할래요 주 행동·NativeSheet를 유지한다. 단일/루틴의 원본 제목과 새 내 항목·소유권을 설명한다.
- 응원은 계정/세션별 목록·상세 공유 상태에서 낙관 표시·실패 원복·중복 잠금·같은 키 명시 확인을 제공한다. 현재 상태 GET은 새 POST를 만들거나 불확실 요청을 지우지 않는다. 5분/역행 후 toggle 재전송을 차단하며 만료 작업의 자동 해제는 후속 서버 계약 범위다.
