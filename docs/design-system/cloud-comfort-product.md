# 뭉실 제품·디자인 시스템 v2.0 — Cloud Rhythm

이 문서는 뭉실의 제품 판단과 프론트 구현에서 사용하는 단일 디자인 기준이다. Stitch 결과물의 정보 위계는 참고하되 원본 HTML이나 외부 에셋을 복사하지 않는다. 모든 화면은 현재 Next.js 구조와 실제 API 계약 위에서 구현한다.

## 1. 제품의 한 문장

> 뭉실은 다른 사람의 좋은 실천을 구경하는 데서 끝내지 않고, 내 오늘로 가져와 직접 완료하게 만드는 TODO 소셜 서비스다.

### 핵심 사용자

- 자기관리를 원하지만 경쟁적인 생산성 앱에는 피로를 느끼는 20~40대
- 거창한 목표보다 오늘 실행할 수 있는 작은 행동이 필요한 사람
- 타인의 기록에서 아이디어를 얻되 과시와 비교보다 다정한 응원을 원하는 사람

### 핵심 순환

`TODO 만들기 → 완료하기 → 피드에 게시하기 → 응원·댓글 받기 → 다른 실천 가져오기 → 다시 완료하기`

제품 지표와 화면 우선순위는 이 순환이 얼마나 자연스럽게 이어지는지로 판단한다. 팔로워 수, 포인트, 챌린지는 핵심 순환을 돕는 보조 장치다.

## 2. 제품 경험 원칙

### 2.1 오늘 먼저

- 앱을 열면 통계보다 지금 해야 할 한 가지가 먼저 보여야 한다.
- 진행률은 동기를 보조하되 첫 화면의 절반 이상을 차지하지 않는다.
- 한 화면의 주 행동은 하나만 가장 강하게 표현한다.

### 2.2 성취는 따뜻하게, 실패는 조용하게

- 완료 순간에는 짧고 분명한 축하와 게시 선택지를 제공한다.
- 미완료, 연속 기록 중단, 낮은 등수에 죄책감을 유발하는 문구를 쓰지 않는다.
- 삭제·오류·권한 제한은 원인과 다음 행동을 함께 안내한다.

### 2.3 구경에서 실행으로

- 피드의 주 행동은 항상 `나도 할래요`다.
- 가져오기 전 제목, 날짜, 시간, 카테고리, 반복을 수정할 수 있다.
- 단일 TODO인지 여러 TODO로 구성된 루틴인지 카드에서 바로 구분된다.
- 루틴 가져오기는 항목별 반복을 보존하는 것이 기본이며, 반복 없이 가져오기와 항목별 날짜·시간·반복 편집을 선택할 수 있다.

### 2.4 실제 기록이 주인공

- 탐색에서는 인증 사진과 연결된 실천 제목을 가장 크게 보여준다.
- 구름 캐릭터는 로고, 빈 상태, 완료, 등급 상승에만 사용한다.
- 장식용 구름, 과한 그라데이션, 유리 효과를 콘텐츠 위에 반복하지 않는다.

### 2.5 예측 가능한 안전함

- 같은 행동은 모든 화면에서 같은 위치, 이름, 상태 변화로 동작한다.
- 낙관적 업데이트가 실패하면 이전 상태로 되돌리고 재시도 방법을 보여준다.
- 공개 범위와 데이터 소유권은 작성·게시·가져오기 전 과정에서 명확해야 한다.

## 3. 정보 구조와 화면별 주 행동

| 영역 | 사용자의 질문 | 첫 화면의 주 행동 | 보조 행동 |
| --- | --- | --- | --- |
| 오늘 | 지금 무엇을 하면 되지? | 현재 TODO 완료 | TODO 추가, 완료 항목 게시 |
| 탐색 | 무엇을 따라 해볼까? | 나도 할래요 | 검색, 필터, 응원, 댓글 |
| TODO | 언제 무엇을 계획했지? | 선택 날짜에 TODO 추가 | 주/월 전환, 편집, 루틴 묶기 |
| 챌린지 | 함께 얼마나 이어가고 있지? | 오늘 인증 또는 참여 | 상세 보기, 참여 취소 |
| 마이 | 나는 어떻게 성장하고 있지? | 기록 확인 | 프로필 편집, 배지, 설정 |

전역 내비게이션은 `오늘 · 탐색 · TODO · 챌린지 · 마이` 다섯 탭이다. 알림은 헤더에서 진입한다. 게시물 상세, 가져오기, 작성·편집은 작업 집중 화면으로 열며 필요한 경우 하단 탭을 숨긴다.

## 4. 브랜드 성격

### Cloud Rhythm

기존 Cloud Comfort의 포근함에 실제 행동의 리듬을 더한다.

- **Calm**: 여백, 크림색 바탕, 낮은 채도의 넓은 색면
- **Clear**: 높은 텍스트 대비, 한 화면 하나의 주 행동, 분명한 상태
- **Human**: 평가보다 응원, 짧고 자연스러운 한국어
- **Gently playful**: 완료와 성장 순간에만 나타나는 구름과 작은 탄성

시각 비율은 `차분함 70 · 명료함 25 · 귀여움 5`로 유지한다. 아동용 캐릭터 앱이나 기업용 대시보드 어느 쪽으로도 치우치지 않는다.

## 5. 디자인 토큰

### 5.1 색상

| 의미 토큰 | 기본값 | 사용 |
| --- | --- | --- |
| `canvas` | `#EEECEA` | 데스크톱 바깥 배경 |
| `background` | `#FAF8F5` | 모바일 앱 바탕 |
| `surface` | `#FFFFFF` | 카드, 시트, 내비게이션 |
| `surface-subtle` | `#F3F1EF` | 입력, 비활성 영역 |
| `text-primary` | `#202027` | 제목과 본문 |
| `text-secondary` | `#66616C` | 설명과 메타데이터 |
| `border` | `#E5E0E6` | 구분선과 기본 경계 |
| `brand` | `#65558F` | 핵심 CTA, 포커스, 선택 |
| `brand-strong` | `#514276` | 눌림·호버 상태 |
| `lavender` | `#E8DEFF` | 계획, 추천, 등급 |
| `aqua` | `#C3ECE9` | 완료, 활성 탭, 안정 상태 |
| `blush` | `#FFDCE4` | 응원, 관계, 따뜻한 강조 |
| `butter` | `#F3F2C9` | 안내, 포인트, 주의 |
| `success` | `#2F6B66` | 성공 텍스트와 아이콘 |
| `danger` | `#B3261E` | 오류와 삭제 |

- 넓은 파스텔 색면에는 짙은 텍스트를 사용한다. 흰색 텍스트는 `brand` 이상의 짙은 배경에서만 쓴다.
- 색만으로 상태를 표현하지 않고 아이콘, 레이블, 형태를 함께 사용한다.
- 한 화면에서 파스텔 강조색은 주색 하나와 보조색 하나까지만 쓴다.

### 5.2 타이포그래피

기본 서체는 `Plus Jakarta Sans Variable`, 한글은 시스템 산세리프 폴백을 사용한다.

| 역할 | 크기/행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| Display | 32/40 | 760 | 랜딩 핵심 문장 |
| Page title | 28/36 | 760 | 화면 제목 |
| Section title | 20/28 | 720 | 섹션 제목 |
| Card title | 16/23 | 700 | TODO·피드 제목 |
| Body | 14/22 | 500 | 설명과 본문 |
| Label | 13/18 | 700 | 버튼·필드 레이블 |
| Meta | 12/17 | 650 | 시간·카테고리·수치 |

- 본문과 버튼은 13px 미만으로 만들지 않는다. 메타데이터의 최솟값은 12px이다.
- 한글 제목은 `word-break: keep-all`, 긴 사용자 콘텐츠는 적절한 줄바꿈과 말줄임을 사용한다.
- 모든 숫자는 같은 화면에서 동일한 굵기와 단위를 사용한다.

### 5.3 간격·크기·형태

- 기본 단위: 4px. 주 간격 계열: `4, 8, 12, 16, 20, 24, 32, 40, 48`.
- 화면 좌우 여백: 360px에서 18px, 390~430px에서 20px.
- 카드 안쪽 여백: 16px, 핵심 카드 20~24px.
- 터치 영역: 최소 44×44px. 주요 CTA 높이: 52px.
- 모서리: 입력 14px, 일반 카드 18px, 핵심 카드·시트 24px, pill 999px.
- 모바일 제품 폭: 최대 430px. 데스크톱에서는 중앙 프레임, 실제 모바일에서는 전체 화면.

### 5.4 깊이

- `level 0`: 배경, 그림자 없음
- `level 1`: 일반 카드, 얇은 경계 + `0 8px 24px rgba(54, 46, 67, .06)`
- `level 2`: 현재 할 일, 피드 카드, `0 14px 36px rgba(54, 46, 67, .10)`
- `level 3`: 시트와 고정 내비게이션, `0 20px 52px rgba(54, 46, 67, .16)`
- blur는 앱 헤더·하단 내비게이션의 바깥 배경 분리에만 제한적으로 사용한다.

### 5.5 모션

주 성격은 **차분한 Professional**, 완료 순간에만 **절제된 Playful**을 빌린다.

- 대표 easing: `cubic-bezier(.2, 0, 0, 1)`
- 빠름 120ms: 누름, 포커스, 아이콘
- 기본 220ms: 카드 상태, 탭 선택, 인라인 알림
- 느림 360ms: 시트 등장, 완료 축하
- 화면 진입: 아래 8px + opacity, 220ms
- 버튼 누름: scale `.97`, 120ms
- 완료: 체크 scale pop + 카드 색 전환, 360ms 이내
- 오류: 색 전환과 인라인 안내를 우선하며 흔들림은 한 번, 최대 300ms
- `prefers-reduced-motion`에서는 공간 이동과 탄성을 제거하고 짧은 opacity 변화만 남긴다.

지속적으로 떠다니는 장식, 큰 확대/축소, 자동 패럴랙스는 사용하지 않는다.

## 6. 공통 컴포넌트 계약

### 앱 셸

- 헤더는 56px 높이의 단단한 Surface다. 로고, 브랜드, 알림/로그인의 세 영역을 유지한다.
- 하단 탭은 Safe Area를 포함한다. 활성 탭은 aqua pill과 아이콘·레이블로 표시한다.
- 페이지 스크롤은 하나만 존재하며 콘텐츠가 하단 탭 아래로 숨지 않는다.

### 버튼

- Primary: 화면의 유일한 주 행동. brand 배경, 흰색 텍스트.
- Secondary: Surface 배경, brand 경계 또는 연한 lavender 배경.
- Tertiary: 텍스트·아이콘 행동. 최소 터치 영역은 유지한다.
- Danger: 확인 단계가 필요한 삭제·차단에만 사용한다.
- 모든 버튼에 기본, hover, pressed, focus-visible, disabled, loading 상태를 제공한다.

### TODO 카드

- **현재**: 흰색 Surface, brand 경계, 완료 CTA가 분명하다.
- **예정**: subtle surface, 시간·반복 정보를 보여준다.
- **완료**: aqua 배경, 체크와 완료 레이블, 제목 취소선은 보조적으로 사용한다.
- 완료된 항목에는 `게시`가 보조 행동으로 남는다.

### TODO 그룹

- 여러 TODO는 `TodoList`를 기반으로 한 접을 수 있는 루틴 그룹에 표시한다.
- 그룹 헤더에는 이름, 완료 개수, 진행률, 다음 TODO를 보여주고 항목을 펼치면 세로 연결선으로 실행 순서를 표현한다.
- 반복 TODO는 다음 발생 일정에서도 같은 그룹에 이어지며, 하나의 TODO 또는 반복 시리즈는 기본 그룹 하나에만 속한다.
- 그룹을 접어도 할 일이 사라진 것처럼 보이지 않도록 다음 TODO 요약을 항상 남긴다.

### 피드 카드

- 작성자 → 인증 이미지 → 연결 실천 → 짧은 본문 → 반응/가져오기 순서다.
- 이미지는 4:3 비율, 실제 콘텐츠가 없으면 완료 정보가 담긴 색면을 쓴다.
- `나도 할래요`는 항상 가장 강한 버튼이다. 응원과 댓글은 아이콘+수치 행동이다.
- 루틴에는 TODO 개수, 단일 TODO에는 `단일 TODO` 레이블을 표시한다.

### 입력과 시트

- 레이블은 입력 위에 두고 도움말·오류는 입력 바로 아래에 둔다.
- 포커스는 2px brand ring으로 표시한다.
- 시트는 제목, 닫기, 본문, 하단 CTA 순서이며 Esc·배경 클릭·포커스 트랩을 지원한다.
- 업로드는 선택 파일, 진행률, 실패 원인, 다시 시도를 한 흐름에서 보여준다.

### 상태 화면

- 로딩: 콘텐츠 형태를 닮은 skeleton.
- 빈 상태: 구름 마크 + 상황 설명 + 가능한 다음 행동.
- 오류: 원인에 가까운 문구 + 재시도.
- 오프라인: 상단 고정 배너, 쓰기 행동은 재연결 안내.
- 권한 없음: 로그인 또는 돌아갈 위치를 명확히 제공한다.
- 성공: 자동으로 사라지는 정보만 토스트에 두고 중요한 결과는 화면에 남긴다.

## 7. 화면 청사진

### 오늘

`인사와 날짜 → 간결한 진행 카드 → 지금 할 일 → 오늘의 전체 목록` 순서다. 첫 700px 안에 현재 TODO와 완료 버튼이 보여야 한다. TODO 추가는 목록 헤더 한 곳으로 통일한다. 완료 후 게시 시트는 선택이며 닫아도 완료 기록은 유지된다.

### 탐색

기본 탐색은 `화면 제목과 필터·검색 → 사진 중심 피드` 순서로 최소화한다. 피드의 주 행동은 `나도 할래요`이며 비회원도 공개 콘텐츠를 보되 응원·댓글·가져오기에서 로그인으로 연결한다.

- 검색은 기본 피드의 상단 아이콘으로 `/explore/search` 전용 화면에 진입한다. 피드에는 검색창, 인기 태그, 추천 루틴, 관심사 칩을 섞지 않는다.
- 피드 필터는 공통 시트에서 관심사와 `최신순·추천순`을 선택하고 URL에 보존한다. 기본값은 `전체·최신순`이다.
- 검색 전용 화면은 최근 검색과 인기 해시태그를 보여주고, 검색 후에는 `통합 · 사용자 · 실천 · 루틴 · 해시태그 · 챌린지` 결과를 구분한다.
- `@`로 시작한 검색어는 사용자, `#`로 시작한 검색어는 해시태그 결과를 우선한다. 선택한 결과 종류와 검색어는 URL에 보존한다.
- 공개 게시물에 연결된 TODO·루틴 제목만 검색하며 비공개 TODO나 비공개 게시물은 검색 결과와 결과 수에 포함하지 않는다.
- 게시 해시태그는 5개까지 허용하고 글자·숫자·밑줄로 정규화한다. 피드 태그를 누르면 검색 전용 화면으로 이동한다.

### TODO

TODO 영역은 `일정 · 그룹 · 카테고리`의 세 관리 화면으로 나눈다. 일정은 압축된 주간 탐색과 선택 날짜의 TODO를 모두 펼쳐 보여주며, 같은 그룹은 얇은 경계와 작은 라벨로 한 번 더 묶되 개별 TODO보다 강하게 강조하지 않는다. 월간 달력은 시트로 열고 선택 날짜는 URL에 남긴다. 그룹은 별도 화면에서 생성·구성·관리하며 피드에 발행할 때만 `루틴으로 게시`라고 표현한다. 그룹 편집에서는 선택된 TODO를 먼저 보여주고 각 TODO의 날짜·시간·반복·기존 그룹 소속을 함께 표시한다. 카테고리는 기본 8개 공개 분류를 유지하면서 사용자 이름·색상·순서·보관을 관리한다. 기본 화면은 갤러리로 구성하고 카드의 넓은 색면을 누르면 해당 카테고리의 전체·예정·완료 TODO를 공통 시트에서 확인한다. 시트의 TODO는 해당 날짜의 일정 화면으로 이어진다. 편집·숨김은 카드의 목록 진입과 분리된 보조 행동으로 두고, 순서 변경은 별도 시트에서 드래그와 키보드·맨 위/아래 빠른 이동으로 처리한다. 사용자 카테고리는 공개 탐색에서 연결할 기준 카테고리를 반드시 가진다. 작성·편집은 같은 시트와 필드 순서를 사용한다. 작성·편집 시 `그룹 없음` 또는 기존 그룹 하나를 직접 고를 수 있고 현재 그룹은 미리 선택한다. 반복 TODO의 그룹과 사용자 카테고리는 시리즈 전체에 보존한다.

### 챌린지

`참여 중 → 공식 → 커뮤니티`로 나눈다. 각 카드에서 기간, 참여자, 인증 방식, 내 오늘 상태를 읽을 수 있어야 한다. 참여자는 `오늘 인증`, 미참여자는 `참여하기`가 주 행동이다.

- 커뮤니티 챌린지는 500포인트로 만들며 뭉실 전용 날짜·인증 방식·완주율 선택기를 사용한다. 완주 기준을 충족한 상위 3명에게 설정된 칭호를 자동 지급한다.
- 인증 방식은 `간편 체크`와 `참여자 사진 인증` 두 가지만 새로 만들 수 있다. 간편 체크는 즉시 통과하며 사진과 메모는 선택 기록이다.
- 참여자 사진 인증은 최소 참여자 8명부터 작동한다. 같은 챌린지의 이메일 인증 참여자가 작성자 정보와 현재 투표 수를 보지 않고 기준별로 `확인돼요 · 확인되지 않아요 · 판단하기 어려워요`를 선택한다.
- 다른 참여자의 인증을 확인할 때는 사진을 원본 비율에 가깝게 먼저 보여주고, 여러 기준을 한 화면에 밀어 넣지 않고 한 기준씩 진행한다. 선택지는 최소 60px 높이의 아이콘·제목·설명 카드로 제공하고 현재 단계와 이전 기준 이동을 함께 표시한다.
- 최초 판정은 유효 투표 5명 중 4명 동의 시 통과, 2명 재요청 시 다시 올리기다. `잘 모르겠어요`는 정족수에 포함하지 않고 다른 참여자의 판단으로 보충한다.
- 다시 올리기는 원래 인증 날짜를 유지하며 24시간 안에 할 수 있고 하루 최대 3회다. 같은 사진 재검증은 한 번만 가능하며 7명 중 5명 동의 또는 3명 재요청 기준을 쓴다.
- 공식 챌린지는 운영자만 만들고 수정·종료할 수 있다. 보상이 있는 공식 챌린지는 참여자 사진 인증을 사용하며 통과 인증만 성공률과 순위에 반영한다.
- 상세 화면은 내 진행률, 익명 확인 진행 수, 다시 올리기, 보상 상태, 통과 인증 기반 순위를 한 흐름으로 보여준다. 재요청 상태를 벌점처럼 표현하지 않는다.
- 참여 취소와 챌린지 종료는 공통 확인 시트를 사용한다. 종료된 챌린지는 직접 ID 참여·인증도 서버에서 차단한다.
- 공식 보상 대상은 종료 후 완주율로 자동 분류하고 운영자가 `검수·승인·지급` 상태를 관리한다. 상태 변화와 커뮤니티 칭호 지급은 앱 알림으로 연결한다.

#### 챌린지 대화방

- 대화방은 챌린지 참여자가 팁, 주의점, 사용 경험을 나누는 보조 경험이다. 챌린지 상세의 오늘 인증을 주 행동으로 유지하고 대화방 진입은 별도 보조 카드로 둔다.
- 대화 화면은 하단 5탭을 숨긴 집중 화면이다. `.app-scroll`이 메시지와 이전 기록의 유일한 세로 스크롤을 소유하고, 헤더와 작성창만 sticky로 유지한다.
- 텍스트 2,000자 또는 사진 4장까지 보낼 수 있다. 링크는 외부 내용을 가져오지 않고 정리된 주소와 도메인만 표시한다. 답장, 5분 내 수정, 수정 이력, 삭제 자리표시자와 고정 5종 반응을 제공한다.
- 위쪽 기록을 보는 중 새 메시지가 와도 위치를 강제로 바꾸지 않는다. `새 메시지 N개` 버튼으로 사용자가 최신 위치로 이동하게 한다. 입력 중, 온라인 상태, 다른 사람의 읽음 여부는 노출하지 않는다.
- 차단한 사용자의 메시지는 한 건씩 열 수 있는 접힌 상태로 표시한다. 방별 알림은 `모든 메시지 · 내 메시지의 답장만 · 알림 없음`이며 알림 센터에는 방별 항목 하나와 최신 내용·안 읽은 수를 유지한다.
- 커뮤니티 방장은 사유를 남겨 메시지 숨김·복구와 24시간·7일 채팅 제한·조기 해제만 할 수 있다. 공식 방은 운영자만 제재한다. 운영자는 신고 메시지와 앞뒤 3개, 수정 이력, 첨부 사진만 감사 기록과 함께 확인한다.
- 참여 취소 즉시 접근을 제거한다. 다시 참여하면 과거 기록은 보이지만 남은 채팅 제한은 유지한다. 종료 시 읽기 전용으로 전환하고 지난 챌린지에서 90일 동안 제공한 뒤 사진과 수정 이력·반응을 포함해 삭제한다.

### 1:1 대화

- 5개 핵심 탭은 유지하고 전역 헤더의 대화 아이콘에서 대화함으로 들어간다. 대화 상세만 하단 탭을 숨긴 집중 화면으로 사용한다.
- 공개 프로필의 `메시지`는 보조 행동이다. 서로 팔로우 중이면 대화를 즉시 열고, 그 외에는 상대가 수락하거나 거절할 수 있는 메시지 요청을 보낸다.
- 대화함의 메시지 요청은 설명이나 큰 아이콘 없이 48px 한 줄 요약과 개수만 노출한다. 연한 lavender 색면으로 최근 대화와 구분하고, 선택하면 공통 시트에서 수락·거절한다. 1:1 대화와 내가 참여한 챌린지 대화방은 하나의 최신순 목록에 모으고 `1:1·챌린지·종료됨` 텍스트 라벨, 마지막 메시지, 시각, 안 읽은 수로 구분한다. 검색·온라인 상태는 초기 베타에 넣지 않는다.
- 메시지는 텍스트 2,000자 또는 사진 4장까지 지원한다. 답장, 고정 5종 반응, 내 메시지 삭제 자리표시자와 신고를 제공하며 REST 저장 성공 뒤 소켓으로 갱신한다.
- 위쪽 기록을 읽는 동안 새 메시지가 와도 위치를 이동하지 않고 `새 메시지 N개` 버튼을 제공한다. 연결이 끊기면 15초 조회로 복구한다.
- 차단 관계는 대화 생성·요청·메시지·반응의 모든 변경 요청에서 다시 확인한다. 차단 뒤에도 기존 기록은 보존하지만 새 메시지는 보낼 수 없다.

### 마이

`프로필 → 핵심 통계 → 뭉실 등급 → 완료·게시·가져온 기록 → 배지 → 설정` 순서다. 숫자는 경쟁 순위보다 개인의 누적과 다음 단계에 초점을 둔다.

### 운영 센터

운영자 화면은 일반 사용자 경험과 분리하되 같은 모바일 프레임과 입력 규칙을 사용한다. `현황 → 사용자·초대 → 신고·콘텐츠 → 챌린지 → 행동 기록` 순서로 구성하며, 각 화면은 서버 셸이나 DB 직접 수정 없이 하나의 운영 과업을 끝낼 수 있어야 한다.

- 현황은 전체 사용자, 7일 활성 사용자, 처리 대기 신고·인증, 활성 초대 코드와 `TODO 완료 → 게시 → 가져오기` 행동 수만 표시한다. 개인의 TODO 본문은 지표에 노출하지 않는다.
- 초대 코드 원문은 발급 직후 한 번만 보여주며 목록에는 이름, 사용량, 만료, 활성 상태만 표시한다.
- 사용자 정지는 구체적인 사유를 필수로 받고 활성 세션을 즉시 폐기한다. 관리자와 중재자는 사용자 목록에서 직접 제재할 수 없다.
- 게시물·댓글 숨김은 원문 미리보기와 신고 건수를 함께 확인한 뒤 사유를 남긴다. 복구는 별도 확인 흐름으로 제공한다.
- 운영자는 개별 사진 인증을 승인·반려할 수 없다. 대기 수, 12시간 이상 지연, 24시간 자동 판정 결과, 참여자 풀 부족만 모니터링한다. 참여자는 투표 화면에서 부적절한 사진을 신고하고, 운영자는 신고 사진을 확인해 판정과 별개로 숨길 수 있으며 사유·알림·감사 기록을 남긴다.
- 초대 발급, 사용자 제재, 콘텐츠 숨김, 신고 상태, 챌린지 보상 변경, 대화방 메시지 숨김·복구와 참여자 채팅 제한은 관리자 ID와 시각이 포함된 감사 기록으로 남긴다.
- 운영 화면도 native `select`, 날짜 입력, 브라우저 확인창을 쓰지 않고 공통 `Sheet`와 최소 44px 터치 영역을 지킨다.

### 인증·온보딩

한 화면에 한 단계만 요청한다. 가입은 입력 오류와 서버 오류를 구분하고, 가입 완료와 메일 발송 실패를 별개 상태로 보여준다. 체험 모드는 개발 환경에서만 보인다.

## 8. 문장 스타일

- 명령보다 제안: `완료하세요`보다 `완료하기`, `실천해볼까요?`
- 막연한 감성 문구보다 상태: `새로운 여정`보다 `오늘 2개 남았어요`
- 실패를 사용자 탓으로 돌리지 않기: `잘못 입력했습니다`보다 `이메일 형식을 확인해주세요`
- 핵심 버튼은 동사+대상: `저장`보다 `내 TODO에 저장`
- `TODO`, `루틴`, `실천`, `게시`, `응원`, `가져오기` 용어를 화면 전체에서 통일한다. `공유`는 외부 링크나 Web Share 기능에만 사용한다.

## 9. 접근성·반응형 완료 기준

- 360px, 390px, 430px와 PC 중앙 프레임에서 가로 스크롤, 이중 스크롤, 탭 겹침이 없다.
- 모든 인터랙션은 키보드로 도달할 수 있고 `focus-visible`이 보인다.
- 아이콘 단독 버튼은 한국어 접근성 이름을 가진다.
- 본문/배경과 버튼/배경은 WCAG AA 대비를 만족한다.
- 모달은 포커스를 가두고 Esc로 닫히며 닫은 후 원래 요소로 포커스가 돌아간다.
- 이미지에는 목적에 맞는 대체 텍스트를 제공하고 장식 이미지는 빈 대체 텍스트를 쓴다.
- 200% 확대에서도 핵심 행동과 텍스트가 잘리지 않는다.
- 축소 모션 설정에서 기능 정보가 사라지지 않는다.

## 10. 구현 규칙과 완료 체크

- API 상태와 예시 데이터를 한 화면에서 섞지 않는다.
- 공통 토큰과 컴포넌트 상태를 먼저 수정하고 화면별 예외 CSS는 최소화한다.
- Lucide 아이콘과 현재 로컬 제품 자산을 사용한다.
- Stitch 외부 이미지와 CDN 코드는 운영 코드에 포함하지 않는다.
- 모든 화면에 정상, 로딩, 빈 상태, 오류, 오프라인, 권한 없음 중 해당 상태를 구현한다.

프론트 변경은 아래 항목을 모두 통과해야 완료로 본다.

1. 핵심 순환의 주 행동이 각 화면에서 하나만 가장 강하게 보인다.
2. 첫 화면에서 사용자가 현재 상태와 다음 행동을 5초 안에 이해할 수 있다.
3. 44px 터치 영역과 12px 메타 텍스트 최솟값을 지킨다.
4. `prefers-reduced-motion`을 포함한 포커스·모달·상태 피드백이 동작한다.
5. 360/390/430px 레이아웃과 데스크톱 중앙 프레임을 만족한다.
6. 린트, 테스트, 프로덕션 빌드가 통과한다.
