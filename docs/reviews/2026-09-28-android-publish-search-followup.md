# Android 게시·검색 후속 구현

2026-09-28. 실제 Google 확인을 보류한 상태에서 C3의 게시 폼·사진 초안·검색을 이어서 보완했다. Kotlin/Compose와 기존 API를 유지하며 새 서버 변경·배포·AAB 제작·Play 업로드는 하지 않았다. 앞선 팔로우 서버 변경은 여전히 별도 배포가 필요하다.

## 동작과 사용 흐름

- 게시 시트 제목·소개·사진 → 한마디 → 태그 추가/삭제 → 공개 범위 → 게시 순서를 현재 웹에 맞췄다. 전체 공개/팔로워/나만 보기 설명·아이콘·선택 표시를 함께 제공한다. 사진 촬영·선택은 Android 흐름을 유지한다.
- 태그는 NFKC·한국어 소문자 정규화, 앞의 # 제거, 중복 제거, 5개/30자 제한을 적용한다. Enter/IME 완료·쉼표·추가 버튼으로 확정하고 개별 삭제한다. 잘못된 입력은 편집 가능한 초안으로 남으며 확정 목록을 바꾸지 않는다.
- 공개 범위만 바꿔도 닫기에 확인이 필요하다. 저장 중 한마디·태그·범위·사진 조작과 중복 게시를 막는다. 게시 실패 후 초안·성공한 미디어 ID·동일 제출 키를 복원하고, 사진 제외나 태그 변경 후 새 요청에는 새 키를 사용한다.
- 사진 선택 URI와 촬영 URI는 바이트 대신 `PhotoDraft`로 저장한다. 게시 폼은 이 상태를 시트 바깥에서 보유하며 미완료 URI·미디어 ID·진행 상태를 함께 확인해 복원 직후에도 게시를 막는다. 성공한 미디어 ID가 있으면 재시도에서 다시 업로드하지 않는다.
- 검색은 사용자·해시태그·실천·루틴·챌린지 섹션, 서버 전체 수치, 결과 유형과 더보기, 사용자 등급·챌린지 종류/인원/설명을 제공한다. 통합 화면의 실천 3개/루틴 2개 미리보기와 전용 유형의 전체 응답 목록은 웹과 같다. API에 없는 추가 검색 커서는 만들지 않았다.
- 최근 검색 6개·중복 제거·재검색·모두 지우기, 미제출 검색 입력과 선택 유형의 복원을 유지한다. 조회 실패/잘못된 응답과 실제 0건 결과를 구분한다. 검색어·결과 유형·최근 검색·목록은 LazyList 구성 전에 스냅샷으로 읽는다.
- `SearchRepository`/명시 모델/`SearchModel`의 불변 StateFlow·요청 세대를 도입했다. 이전 검색의 늦은 응답을 무시하고 현재 검색어와 결과가 다르면 이전 기록이나 오류를 새 검색의 결과로 표시하지 않는다.

주요 파일: `PublishDraft.kt`, `PublishSheet.kt`, `PhotoDraft.kt`, `SearchRepository.kt`, `SearchModel.kt`, `SearchScreen.kt`. 테스트: `PublishDraftTest.kt`, `SearchModelTest.kt`, `PublishSearchFlowTest.kt`, 기존 `NativeFlowTest.kt`의 게시·캡처 시나리오.

## 재현한 문제와 검사 경계

- 선택 URI를 시트 안의 로컬 저장 상태에만 두면 저장 상태 복원에서 미완료 사진의 선택 상태를 놓칠 수 있었다. 게시 폼 바깥의 상태로 옮긴 뒤 미완료 첨부로 게시 요청이 나가지 않는지 다시 검사했다.
- 기존 게시 키는 `remember(payload)`라 저장 상태 복원 후 바뀌었다. 공통 `DraftSubmission`으로 제출한 내용과 키를 함께 복원한다. 실패한 두 요청의 본문/키 일치, 미디어 제외·태그 삭제 후 본문/키 변경을 합성 HTTP로 검사한다.
- 저높이 검색 검사에서는 LazyList의 화면 밖 결과를 스크롤하지 않고 기다리는 잘못된 검사를 보완했다. 공유 캡처는 탭에 보존된 게시물→프로필→팔로우 목록 스택을 뒤로 가기로 돌아온 뒤 탐색을 연다. 실제 탐색 정책을 캡처 편의로 바꾸지 않았다.
- 사진 기기 검사는 테스트 선택기 콜백으로 실패·완료·제외를 주입하고, 별도 검사에서 실제 `PhotoPicker`가 앱 FileProvider의 합성 JPEG를 읽어 MIME/크기를 presign 요청에 보내는 것을 확인했다. presign 실패 후 제외하면 오류·재시도 표시가 정리되고 새 선택이 가능하다. 실제 OS 선택기·파일 권한 복원·HTTPS PUT/완료·S3 성공의 증거가 아니다. `StateRestorationTester`는 저장 상태 복원이며 실제 프로세스 종료가 아니다.
- 웹/앱 공유 캡처는 같은 fixture를 사용한다. TODO 조회의 날짜만 양쪽 모두 현재 서울 날짜로 투영하고 원본 시간을 유지한다. 나머지 기록은 같은 fixture 원문이다. 실제 DB 관계의 일관성 판정은 별도다.

## 로컬 검증

Android 단위 검사 48/48과 lint·앱/검사 APK 빌드는 통과했다. 신규 기기 5개 검사와 기존 게시 3개 검사는 통과했다. 게시·검색의 360/390/430dp·저높이·글꼴 200%, 공유 캡처와 기존 저높이 순환은 11조건에서 합계 23회 통과했다. 이는 여러 실행의 최종 성공 결과를 합친 수치이며 단일 실행으로 표시하지 않는다. 최종 전체 연결 검사 43/43도 통과했다. 원시 전체 로그는 `publish-search-connected43.log`에 보존한다. 저장소 lint·테스트·API/Web 전체 빌드는 통과했다. API는 115 통과·4 skip, Web은 53/53 통과다. 웹과 앱 모두 공유 데이터 10개 화면 및 게시 시트 × 3폭 캡처를 확보했다.

원시 결과는 `outputs/android/native-verification/publish-search-*.log`, `publish-photo-final.log`와 각 조건의 `*-tests.txt`, 합계는 `publish-search-matrix-results.json`, 비교 문서는 `outputs/android/parity-comparison.html`에 기록한다. 이전 실패 로그도 보존하며 미실행 검사를 통과로 표시하지 않는다.

## 남은 범위

- C3의 실제 OS 사진 선택/촬영·업로드·권한 복원과 C4 두 계정 HTTP/DB 핵심 순환은 남는다. 프로필·챌린지·채팅의 미완료 URI 복원은 각각의 폼 소유 상태와 함께 추가 대조해야 한다.
- 실제 Google·FCM·API 24·실기기 키보드/TalkBack·회전/프로세스 종료·격리 DB/스토리지/소켓은 이번 검사로 완료하지 않는다.
- 비교 확보는 10/28개 화면과 게시 시트이며 시각 동등성 통과율이 아니다. 카드·입력·탭·여백·시트 높이 등의 차이를 비교 문서에 남긴다.
- 다음 로컬 우선 작업은 챌린지 생성/편집/기간/역할과 반려·사진 재인증·기준별 검수, 알림 동시 읽음·계정 종료/링크다. 전체 진행률은 약 62% 작업량 추정이며 기존 1.2.0(5) AAB에는 이번 변경이 포함되지 않는다.
