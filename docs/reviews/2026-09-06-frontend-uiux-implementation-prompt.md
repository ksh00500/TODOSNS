### 2. 변경하면 안 되는 제품 방향

- 핵심 순환: TODO 생성 → 완료 → 게시 → 응원·댓글 → 가져오기 → 다시 완료.
- 5개 탭: 오늘·탐색·TODO·챌린지·마이. 메시지 화면은 별도이며 핵심 탭을 교체하지 않는다.
- 크림 바탕, 남색 텍스트, 파스텔 색면, 차분한 20~40대 라이프스타일 톤을 유지한다.
- PC에서도 중앙 최대 430px 프레임이다. 태블릿 폭이라고 앱을 600~700px로 늘리지 않는다.
- 한 화면의 가장 강한 주 행동은 하나다. 밀도는 불필요한 여백·반복 설명·장식을 줄여 개선한다. 44×44px 터치 영역이나 가독성을 줄이지 않는다.
- 일반 페이지는 `.app-scroll`, 시트는 `.sheet-body`가 세로 스크롤을 소유한다.
- 공통 Sheet의 body 포털, inert, 배경 잠금, 포커스 관리, Safe Area 계약을 유지한다.
- native select/날짜·시간 picker, window.alert/confirm/prompt로 우회하지 않는다.
- 일정은 전체 TODO를 펼친 상태에서 얇은 그룹 경계로 묶는다. 그룹 관리는 별도 화면, 카테고리는 갤러리와 전용 순서 편집 시트를 유지한다.
- 내부 발행은 ‘게시’, 외부 링크 전달은 ‘공유’다. ‘그룹/반복/공개 루틴’의 의미를 구별하며 무작정 전역 치환하지 않는다.
- 데모 데이터와 실제 데이터를 혼합하지 않는다. 운영 인증·권한을 느슨하게 해서 UI 테스트를 통과시키지 않는다.

### 3. 단계 A — 공통 동작과 접근성부터 수정

대상: 감사 보고서 UX-01, UX-02, UX-06, UX-07, UX-08, UX-09.

1. 중첩 시트 문제를 먼저 재현하고 고쳐라.
   - 1:1 메시지 메뉴 → 삭제 확인 → Esc에서 스크롤 잠금이 남는 사례를 회귀 테스트로 만든다.
   - 한 시트로 전환할 수 있는 메뉴/확인 흐름은 전환한다.
   - 중첩이 필요한 경우 최상위 시트만 Esc/Tab/포커스를 처리하게 하고, 마지막 시트가 닫힐 때 잠금이 복구되게 한다.
   - 챌린지 채팅 메뉴와 사진 검수 중 신고 시트도 검사한다.
   - detached element로 포커스를 복구하지 말고, 트리거가 사라졌을 때 합리적인 대체 위치를 둔다.
2. 1280×600에서 700px 최소 높이 때문에 탭이 잘리는 문제와 600px 폭에서 프레임이 커지는 문제를 수정한다.
3. 피드 응원·댓글·프로필 링크의 한국어 접근성 이름, 응원 `aria-pressed`를 제공한다.
4. 달력 7열, 채팅 메뉴/반응, 사진 검수 진입 버튼의 실제 히트 영역과 스타일을 검사한다. 정의되지 않은 `secondary-button` 사용은 공통 스타일로 정리한다.
5. 날짜 선택 후 트리거 포커스 복귀, 시간 선택의 키보드/선택 위치, 검색 탭의 올바른 ARIA와 키보드 탐색, 반복 범위/관심사 선택 상태를 완성한다.
6. 파스텔 면 위 보조 글자의 실제 색 대비를 확인하고 전용 텍스트 토큰으로 고친다. 작은 버튼/본문은 제품 최소 글자 크기를 지킨다.

기존 APG 패턴과 프로젝트 접근성 계약을 따르되, 단순 필터 버튼에 불필요한 탭 역할을 붙이지 마라. 44px은 프로젝트 기준이고 WCAG 2.2 AA의 최소 타깃 기준과 같다고 설명하지 마라.

### 4. 단계 B — 핵심 순환의 실패·초안·관계 보존

대상: UX-03, UX-04, UX-05, UX-11, UX-12.

1. 프론트 오류 처리를 통일한다.
   - 기존 인증 갱신/멱등성 동작을 보존하면서 HTTP 상태와 안전한 사용자용 메시지를 구별한다.
   - 열린 폼의 오류는 열린 시트 안에 표시한다. 부모 배경 notice에만 남기지 않는다.
   - TODO 생성/수정/게시, 응원, 댓글, 팔로우/차단, 메시지 요청, 채팅 변경, 챌린지 참여, 설정 변경의 실패 경로를 점검한다.
   - 401/403/404/409/429/5xx/오프라인에 맞는 행동을 제공한다. 요청 원문/서버 내부 오류를 그대로 노출하지 않는다.
   - 재시도, 낙관적 원복, 중복 제출 차단, 입력 오류 연결을 함께 구현한다.
2. 가져오기 항목별 초안을 모드 전환으로 초기화하지 않는다. 명시적 초기화만 원본으로 되돌린다.
3. 그룹/카테고리의 로딩·오류·실제 없음 상태를 분리한다.
   - 느린 조회 중 제목만 수정해도 기존 그룹이 해제되지 않게 한다.
   - 늦은 응답이 사용자 편집값을 덮지 않게 한다.
   - 필드 생략/null/변경의 실제 API 의미를 확인한다.
4. 새 TODO·편집·가져오기·게시·채팅의 초안과 제출 스냅샷을 안전하게 관리한다.
   - 게시와 인증 사진에 미리보기/제거/진행/실패 상태를 제공한다.
   - 업로드 일부 성공 뒤 실패와 게시 API 실패를 구분하고 가능한 재시도 결과를 재사용한다.
   - 업로드 중 바꾼 새로운 입력까지 성공 콜백에서 지우지 않는다.
   - 폼 이탈은 전용 확인이나 초안 복구로 처리하고, 계정 변경 시 민감한 초안을 남기지 않는다.
5. 지원하지 않는 반복 패턴은 원본 유지로 표시하고, 제목만 편집해도 반복 의미가 바뀌지 않게 한다.
6. 반복 종료는 날짜·범위를 확인하는 전용 확인 시트를 사용한다. 추정한 삭제 개수를 사실처럼 표시하지 않는다.

### 5. 단계 C — 탐색과 TODO 관리의 일관성

대상: UX-10, UX-13, UX-14, UX-18, UX-19.

- 해시태그 클릭 후 같은 태그 카드만 다시 보여주는 흐름을 바꿔 연결된 게시물을 바로 발견하게 한다. 검색 종류 탭, 기존 URL, 공개 범위는 유지한다.
- 작성/편집/가져오기에서 공통 일정·반복·카테고리·그룹 선택 패턴을 사용한다. 필드 지원 차이는 명확히 설명하고 원본 정보를 잃지 않는다.
- ‘루틴 보관함’ 같은 오래된 안내와 잘못된 마이 그룹 링크를 정리한다. 관심사와 사용자 카테고리/기본 탐색 카테고리의 의미를 확인한 뒤 공통 상수 또는 매핑을 사용한다.
- 그룹 구성에서 60일 반복 발생 TODO가 길게 중복돼 보이지 않게 시리즈와 개별 일정의 선택 의미를 드러낸다. 검색/선택 요약을 제공하고 선택할 때 목록 위치를 함부로 바꾸지 않는다.
- 카테고리 갤러리의 반복 설명·보조 관리 버튼 밀도를 줄이되, 소속 TODO 열기와 드래그/키보드 순서 편집을 유지한다.
- 마이/공개 프로필/팔로우/운영 목록에 실제 페이지네이션과 부분 로딩·실패 처리를 연결한다. API가 다음 페이지를 지원하지 않으면 제한을 드러내고 서버 의존성으로 기록한다.
- 로그인/가입/인증 후 원래 작업으로 복귀하는 안전한 내부 returnTo를 유지한다. 검색에서 필터 피드로 돌아오기와 탭 URL 복원도 보완한다.

### 6. 단계 D — 채팅·알림·챌린지 상태

대상: UX-15, UX-16, UX-17.

- 채팅의 방 ID별 초기 위치, 바닥 근처 자동 따라가기, 과거 읽기 위치 보존, 신규 메시지 버튼, 페이지 추가 스크롤 앵커를 일관되게 처리한다.
- 소켓과 폴링으로 같은 메시지를 받아도 중복 카운트하지 않는다. 실제 최신 렌더 메시지를 기준으로 읽음 처리한다.
- 방·`chat-inbox`·앱 셸의 읽음/배지 캐시를 맞춘다. 과거 키 이름만 무효화하는 경로를 정리한다.
- 답장 미리보기의 원문 확인과 답장 작성 행동을 분리한다. 삭제/숨김/차단 원문은 안전한 상태 안내를 제공한다.
- live region은 새 메시지 안내에 제한하고, 처음 로딩한 과거 대화를 한꺼번에 알리지 않는다.
- 알림 읽음은 기존 정책을 확인하고 성공/실패를 정확히 보여준다. 자동 모두 읽음을 다른 정책으로 바꾸려면 변경 의도를 명시하고 필요한 사용자 결정을 받아라.
- 챌린지 시작/종료 날짜와 참여/종료/인증/검수 상태에 맞는 CTA를 제공한다. 종료된 챌린지에 불가능한 참여 버튼을 활성화하지 않는다.
- 현재 사진 검수의 큰 사진·한 기준씩 진행·60px 이상 설명 카드는 유지한다. 확대 보기, 대상 ID 변경 시 답변 초기화, 시트 내부 결과 안내를 보완한다.
- 투표 정족수/무효표/보상/방장 제재/권한 규칙을 이번 UI 작업에서 임의로 변경하지 않는다.

### 7. 단계 E — 회귀 테스트와 실제 검증

소스 문자열 검사만으로 끝내지 마라. 기존 테스트 기반을 먼저 확인하고, 필요한 경우 현재 프로젝트와 호환되는 최소 컴포넌트/브라우저 테스트 도구를 추가해라.

필수 자동 회귀 사례:

1. 중첩 시트 닫기 후 스크롤 잠금/포커스 복구.
2. 날짜 선택 후 트리거 포커스, 시간/검색 선택의 키보드 탐색.
3. 가져오기 모드 왕복 후 제목·시간·반복 보존.
4. 그룹/카테고리 지연·실패 중 관계 보존.
5. 생성/게시 실패가 현재 시트에 표시되고 초안을 유지한 재시도 성공.
6. 변경하지 않은 복합 반복 원본 유지, 반복 종료 확인.
7. 피드 접근성 이름/선택 상태, 해시태그에서 게시물 진입.
8. 채팅 ID 전환·신규 메시지·읽음 캐시와 배지 일치.
9. 첫 페이지를 넘는 목록의 실제 추가 조회.
10. 낮은 PC 창과 360px의 넘침·하단 CTA·44px 타깃.

브라우저 검증:

- 360/390/430px, 600px 중간 폭, 1280×600 PC, 200% 확대.
- 긴 제목/공백 없는 문자열/많은 TODO/그룹/카테고리/사진 미리보기.
- 정상·로딩·빈 상태·오류·권한 없음·오프라인·토큰 만료.
- 키보드 전용·포커스·모달 닫기·선택 상태·색 대비·축소 모션.
- 실제 모바일 키보드는 가능하면 실기기로 검사하고, 단순히 viewport 높이를 줄인 결과와 구분해라.
- 로컬 실제 API와 테스트 계정을 사용할 수 있으면 핵심 순환과 2계정 실시간 채팅을 검사해라. 체험 모드 통과를 실제 DB E2E 통과라고 부르지 마라.

명령 검증:

- 웹 테스트 및 추가한 브라우저 테스트.
- `npm run lint`
- `npm test`
- `npm run build`
- 기존 배포 기준에 맞는 운영 의존성 감사.

실행에 인프라/권한/계정이 필요하면 안전한 로컬 대안을 먼저 확인하고, 실행하지 못한 항목은 정확히 남겨라. 실패를 숨기기 위해 검사 규칙을 끄거나 테스트를 지우지 마라. 운영 빌드 성능은 개발 서버와 구분해 이미지 전송량·초기 번들·LCP/CLS를 실제 측정한 경우에만 수치로 보고해라.

### 8. 작업 경계와 완료 보고

- 운영 배포, Git push, DB 초기화/삭제, 강제 reset은 하지 않는다. 커밋도 별도 요청 없이 하지 않는다.
- 불필요한 프레임워크 교체·CSS 전면 재작성·신규 기능 확장은 하지 않는다.
- 서버 계약 변경이 꼭 필요한 항목은 먼저 계약과 기존 보안 변경을 확인한다. 기존 계약으로 해결할 수 없는 부분은 의존성으로 기록한다. 프론트에서 권한을 우회하거나 데이터가 있는 척하지 마라.
- 읽음 정책·개인정보/법적 문구·제품 권한 등 중요한 결정이 새로 필요하면 근거를 제시하고 질문해라. 명확한 버그 수정과 기존 계약 복원은 계속 진행한다.
- `docs/reviews/2026-09-06-frontend-uiux-remediation-progress.md`를 만들어 UX ID별 `미착수/진행/검증 완료/외부 의존성/해당 없음`과 근거를 기록한다. ‘검증 완료’에는 실제 테스트 증거가 있어야 한다.
- `docs/design-system/uiux-review.md`를 현재 검증 결과로 갱신한다. 재발 방지 규칙이 새로 생겼으면 AGENTS.md와 제품 문서도 필요한 범위에서 보완한다.
- 기존 감사 보고서는 당시 증거이므로 완료 표시로 덮어쓰지 말고, 진행 문서에서 해결 결과를 연결한다.

최종 답변에는 다음을 간결하게 적어라.

1. 실제 수정한 핵심 문제와 사용자 경험 변화.
2. 변경 파일과 진행 문서 위치.
3. 실행한 검사 및 통과/실패 수치.
4. 실행하지 못한 검증과 이유.
5. 남은 UX ID, 서버/계정/정책 의존성.

계획만 세우고 끝내지 말고, 가능한 로컬 수정과 검증을 수행해라. 다만 구현하지 못한 범위를 ‘전체 완료’라고 표현하지 마라.
