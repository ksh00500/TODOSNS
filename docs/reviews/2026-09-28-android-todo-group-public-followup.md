# Android TODO·그룹·공개 프로필 후속 구현

2026-09-28. 사용자 승인에 따라 TODO·그룹·가져오기와 공개 프로필·관계를 진행했다. 실제 Play Google 로그인은 보류했다. 기존 DB·FCM·Docker·CI 미커밋 변경을 보존했으며 운영 서버·DB·사용자 데이터에 접근하지 않았다. 새 AAB 제작·Play 업로드·배포는 하지 않았다.

이 문서의 수치와 남은 범위는 해당 단계 당시 기록이다. 이후 C3와 챌린지 보완의 최신 결과는 [게시·검색 기록](2026-09-28-android-publish-search-followup.md)과 [챌린지 기록](2026-09-28-android-challenge-followup.md)을 참조한다.

## 구현한 동작

- TODO 편집은 원본 복잡한 RRULE과 변경하지 않은 일시의 초·밀리초를 보존한다. `이번 일정만/이후 일정도`를 구분하며 카테고리·그룹 조회 실패나 잘못된 응답 때문에 기존 관계를 비워 저장하지 않는다. 저장 중 입력·선택을 막는다.
- TODO·그룹·카테고리 정렬·루틴 가져오기는 제출 내용과 재시도 키를 함께 저장 상태로 복원한다. 실패한 동일 요청은 같은 키, 제출 내용 변경과 성공 뒤의 새 행동은 새 키를 사용한다. 이 저장 상태에는 인증 자격 증명을 넣지 않는다.
- 그룹 관리 카드에는 구성·완료 수·다음 TODO·관리·루틴 게시를 표시한다. 제목/날짜 검색과 커서 페이지가 바뀌어도 선택을 유지하고 중복 후보를 합친다. 다른 그룹 소속 반복 시리즈 선택을 제한한다. 편집 요청은 공개 범위를 덮어쓰지 않으며 변경 후 닫기는 확인 시트를 거친다.
- 카테고리는 생성 카드·갤러리·보관 목록을 구분한다. 정렬은 별도 시트에서 이동 버튼·접근성 액션·포커스가 있는 행의 Home/End 조작을 제공한다. 소속 TODO 목록은 상태 필터·페이지 추가 조회·계정 시간대의 일정 진입을 제공한다.
- TODO 삭제/되돌리기와 그룹 삭제는 서버의 실제 삭제 범위를 설명한다. TODO 복원으로 게시물·사진을 되살릴 수 없으며 그룹 삭제는 TODO를 유지하지만 연결된 루틴 게시 기록·사진을 삭제한다.
- 공개 프로필에 소개·게시물/팔로워/팔로잉 수치·등급·게시한 실천·응원·가져오기를 연결했다. 서버 응답의 필수 수치와 관계 플래그 누락을 0/false로 숨기지 않는다. 관계 조회 실패 중에는 팔로우·메시지를 막고 재시도를 제공한다. 본인에게 관계 행동을 제공하지 않고 접근 권한 상실 시 이전 기록을 제거한다.
- 팔로우 목록에 방향 선택·사진·닉네임·아이디·등급·커서 추가 조회·중복 제거를 연결했다. 접근할 수 없는 사용자에게 잘못된 프로필 링크를 제공하지 않는다. 차단 해제는 관련 조회를 갱신하며 팔로우나 대화 복원/삭제 API를 호출하지 않는다.

주요 코드: `TodoDraft.kt`, `DraftSubmission.kt`, `GroupForm.kt`, `TodosScreen.kt`, `CategoryOrder.kt`, `FeedScreen.kt`, `PublicProfileRepository.kt`, `PublicProfileModel.kt`, `ProfileScreen.kt`, `ProfileDetails.kt`.

## 확인한 결함과 검증 경계

- `assembleDebugAndroidTest`만 실행하면 테스트 APK는 최신인데 앱 APK가 이전 버전인 상태가 가능했다. 직접 기기 검사 스크립트는 앱과 테스트 APK를 함께 빌드한 뒤 설치한다. 이전 APK로 실패한 결과는 최신 코드 결과로 사용하지 않았다.
- 카테고리 행에 키 이벤트만 있고 실제 포커스가 없어 Home/End가 작동하지 않았다. 포커스와 가시적 표시를 추가하고 키 입력으로 다시 확인했다. 접근성 액션 실행은 실제 TalkBack 세션과 구분한다.
- 그룹 검색 추가 조회 실패 후 선택·중복 제거·필터 변경·저장 상태 복원을 검사했다. 공개 그룹 편집 요청에 visibility를 넣지 않는지 확인했다.
- 반복 TODO는 FUTURE 요청·복잡한 반복·정확한 원본 일시·조회 실패 시 필드 생략·저장 상태 복원 뒤 동일 요청 키를 합성 HTTP로 확인했다. THIS/반복 제거/clone 요청 계약은 별도 단위 검사다.
- TODO 단일 삭제·실패한 복원 재시도·반복 종료의 확인 UI와 요청 대상, 카테고리 목록의 중복 페이지·상태 변경·날짜 전환을 합성 HTTP로 확인했다. 실제 DB의 반복 발생/기록 보존 결과와 동일하다고 판정하지 않는다.
- 공개 프로필의 관계 조회 실패·팔로우 실패/재시도/새 행동 키·메시지 요청 실패/복원·본인 행동 구분·권한 상실·목록 페이지 실패·탈퇴 안내·차단/해제 확인을 합성 HTTP로 검사했다. 지연된 이전 계정/관계 응답을 무시하는 검사는 ViewModel 단위 검사다.

## 서버 변경과 별도 배포 필요 항목

실제 코드 대조에서 `MungsilService.toggleFollow()`가 양방향 차단과 대상 탈퇴/정지 상태를 확인하지 않는 결함을 발견했다. 기존 팔로우 토글 API·응답 계약을 유지하면서 활성 대상 확인과 기존 `assertNotBlocked()` 검사를 추가했다. 양쪽 차단 방향에서 쓰기/알림 없음, 비활성 대상 거부, 정상 팔로우/취소 유지의 4개 동작 검사를 추가했다.

이 서버 변경은 **로컬 코드에만 적용**됐다. 서버에 반영하려면 별도 배포가 필요하다. DB 스키마·migration·운영 설정 변경은 필요하지 않다. 이번 기록은 이전 운영 배포 상태를 확인한 증거가 아니다.

Android 환경은 API 36.1 에뮬레이터이며 합성 HTTP는 기기 내부 loopback이다. 검사 동안 에뮬레이터 인터넷을 끄고 완료 뒤 원래 네트워크·크기·밀도·글꼴 설정을 복원한다. 126회는 서로 다른 기능 126개가 아니라 360/390/430dp에서 전체 38개 검사씩, 저높이/글꼴 200%의 12조건에서 각 1개 검사를 반복한 합계다. 단위 검사와 연결 검사도 별도 숫자이며 서로 더해 기능 수로 사용하지 않는다.

API의 4개 skip은 알림 그룹·핵심 순환·1:1 대화의 실제 DB 검사와 S3 버전 파기 통합 검사다. 새 팔로우 권한 4개 검사는 Prisma 대체 구현을 사용한 동작 검사이며 실제 DB 통합 검사가 아니다. 웹 비교는 공유 합성 fixture를 사용하고 운영 API로 연결하지 않는다. 최초 전체 기기 검사에서 기존 탐색 테스트의 불완전한 프로필 fixture 1건이 실패했으며 실제 계약 필드를 보완한 뒤 전체 행렬을 재실행했다. 실패 기록 `360-incomplete-fixture-tests.txt`를 보존한다.

캡처 확보율은 시각 동등성 통과율이 아니다. 색·계층·주 행동을 대조해도 카드 크기·일부 장식·간격·정보 밀도 차이는 남는다. 공유 비교 문서: `outputs/android/parity-comparison.html`.

## 아직 남은 범위

- 실제 Google·FCM·API 24·실기기 키보드/TalkBack·회전/프로세스 종료는 미검증이다. StateRestorationTester는 저장 상태 복원 검증이며 실제 프로세스 종료가 아니다.
- 격리 PostgreSQL·스토리지·실제 소켓, 웹/앱 두 계정 핵심 순환과 반복/권한/관계 DB 결과는 미실행이다. 운영 자원으로 대체하지 않는다.
- C1/C2의 전체 반복·카테고리 상태 및 드래그/실기기 검수, C3의 모든 검색 결과·게시 사진 실패/복원·게시 폼의 저장 상태 복원 후 제출 키, D4의 실제 두 계정 관계 전이, 챌린지 전체 역할/기간/반려·재인증 흐름은 계속 후속 항목이다.
- 화면 첫 캡처는 9/28개(약 32%)를 확보했다. 오늘·TODO 일정·탐색·게시물·마이·그룹·카테고리·공개 프로필·팔로우 목록을 각 360/390/430에서 비교한다. 전체 28개 화면·시트의 시각 일치 판정은 미완료다.
- 전체 진행률은 약 **60%의 작업량 추정**이며 기능 수나 출시 승인 점수가 아니다. 기존 1.2.0(5) AAB에는 이번 변경이 포함되지 않는다.
