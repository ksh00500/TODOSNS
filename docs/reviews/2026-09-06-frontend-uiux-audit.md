# 뭉실 프론트엔드 디자인·UI/UX 검토

검토일: 2026-09-06
기준: `6fe0682` 및 검토 당시 로컬 작업 트리
성격: 읽기 전용 제품 검토. 아래 항목을 이번 검토에서 구현하거나 수정한 것은 아니다.

## 1. 결론

현재 Cloud Rhythm의 색감, 모바일 프레임, 5탭, TODO 중심 정보 구조는 유지할 가치가 있다. 전면 재디자인보다 **공통 팝업·입력·실패 처리의 안정화 → 핵심 순환 정리 → 채팅과 관리 화면 일관성 → 시각적 마무리** 순서가 적절하다.

겉보기에는 완성된 화면이 많지만, 다음 문제는 실제 브라우저에서 재현됐다.

- 메시지 메뉴와 삭제 확인 시트를 함께 연 뒤 Esc를 누르면 두 시트가 닫히면서 배경 스크롤 잠금이 남는다.
- 가져오기에서 항목별 제목을 수정한 뒤 반복 정책을 전환하면 수정한 제목이 사라진다.
- 높이가 낮은 PC 창에서 모바일 프레임이 화면보다 커져 하단 메뉴가 잘린다.
- 피드 응원·댓글의 접근성 이름이 숫자뿐이고, 일부 프로필 이미지 링크는 이름이 없다.
- 해시태그를 누르면 해당 게시물보다 같은 해시태그 검색 결과로 다시 이동한다.

여기에 코드상 확인되는 조용한 요청 실패, 시트 뒤에 표시되는 오류, 그룹 조회 실패와 ‘그룹 없음’의 혼동이 핵심 데이터 조작 경험을 약하게 만든다. 새로운 장식이나 기능 추가보다 먼저 해결해야 한다.

## 2. 검토 범위와 신뢰 수준

먼저 `AGENTS.md`, `docs/design-system/cloud-comfort-product.md`, `docs/design-system/uiux-review.md`를 읽고 라우트·공통 컴포넌트·CSS·데이터 요청 코드를 검토했다. 기존 UI/UX 문서의 ‘양호’ 표시는 과거 점검 결과이며, 현재 모든 상태가 검증됐다는 뜻으로 사용하지 않았다.

### 수행한 검증

- localhost 개발 서버의 개발용 체험 모드에서 주요 화면과 시트 조작.
- 360·390·430px 주요 화면 점검, 600px 중간 폭, 1280×600 낮은 PC 창 점검.
- 일부 화면을 높이 400px로 줄여 작성창·긴 폼의 공간 부족 상태 확인.
- DOM 접근성 구조, 실제 요소 크기, 스크롤 높이, 활성 포커스, `inert`·overflow 상태 확인.
- `npm run lint -w @mungsil/web`: 통과.
- `npm run test -w @mungsil/web`: 28개 통과.

### 수행하지 않은 검증

- 실제 DB 계정·다중 계정·운영 서버·운영자 계정의 전체 업무 흐름.
- 실제 이미지 업로드, 서버 실패 주입, 토큰 만료, 실시간 소켓 단절/복구.
- 모든 라우트의 모든 상태를 세 가지 폭에서 전수 조작.
- 실제 모바일 키보드, 실제 스크린리더, 200% 브라우저 확대, axe 자동 검사.
- 이번 검토에서 전체 API 테스트, 루트 빌드, 운영 의존성 감사, 프로덕션 성능 측정.

높이를 줄인 브라우저는 모바일 키보드 검증의 대체물이 아니다. 개발 서버·데모의 표시 결과로 운영 LCP나 실제 데이터 무결성을 판정하지 않는다. 기존 웹 테스트에는 소스 패턴 검사가 포함되어 있어, 28개 통과가 아래 상호작용 결함의 부재를 보장하지 않는다.

검토 당시 다른 작업의 배포·보안 수정이 다수 미커밋 상태였다. 그 변경은 수정·되돌리기·커밋하지 않았다. 후속 작업은 현 시점 코드를 다시 확인하고 이미 해결된 항목은 중복 수정하지 않아야 한다.

### 분류

- **재현**: 브라우저에서 직접 관찰한 결과.
- **코드**: 구현에서 확인한 경로·누락·위험. 실패 환경을 실제로 주입한 결과와 구분한다.
- **제안**: 사용성을 높이기 위한 판단. 버그 또는 보안 취약점 확정이 아니다.
- **P1**: 핵심 조작, 입력 보존, 화면 접근을 해치므로 베타 전 우선 수정.
- **P2**: 일관성·접근성·발견성·대량 데이터 대응 보완.
- **P3**: 핵심 안정화 후 다듬을 품질 개선.

## 3. 우선 수정 항목

### UX-01 · P1 · 중첩 시트 종료 후 스크롤 잠금 잔류 — 재현

근거: `apps/web/components/sheet.tsx:25`, `apps/web/app/(product)/messages/[id]/page.tsx:94`.

재현: `/messages/demo-direct-hana` → 기존 메시지의 ‘메시지 메뉴’ → ‘삭제하기’ → 삭제는 확정하지 않고 Esc. 두 `dialog`가 동시에 존재하다 함께 사라졌다. 앱의 `inert`는 해제됐지만 `body.style.overflow`와 `.app-scroll.style.overflow`는 `hidden`으로 남았다.

각 Sheet가 독립적으로 이전 잠금 상태를 저장하고 문서 전체의 Esc를 처리한다. 메뉴를 닫지 않고 확인 시트를 추가하는 호출부와 충돌한다. 챌린지 채팅 메뉴, 사진 검수 중 신고 시트도 함께 점검해야 한다.

수정: 한 번에 하나의 시트로 전환 가능한 흐름은 전환한다. 중첩이 필요한 흐름은 최상위 시트만 키보드·포커스를 소유하도록 공통 레이어 스택과 잠금 소유권을 관리한다. z-index만 변경하지 않는다.

완료: Esc 한 번은 최상위만 닫고, 마지막 시트를 닫으면 원래 스크롤·inert·포커스가 정확히 복구된다. 배경 클릭·취소·닫기·라우트 이탈·반복 열기에서도 동일해야 한다.

### UX-02 · P1 · 낮은 PC 창 잘림과 중간 폭 프레임 확대 — 재현

근거: `apps/web/app/globals.css:84`, `apps/web/app/globals.css:186`.

- 1280×600에서 `.mobile-app`은 높이 700px, 문서 높이는 740px이었다. 하단 탭의 아래쪽은 약 709px로 화면 밖에 있었다.
- 600×800에서는 앱 폭이 600px로 측정됐다. 700px 이하 미디어 규칙이 최대 430px 계약을 덮는다.

수정: 실제 사용 가능한 높이 안에서 프레임을 줄이고, 모든 폭에서 최대 430px을 유지한다. 단순히 바깥 overflow를 숨겨 잘린 콘텐츠를 은폐하지 않는다. 페이지는 `.app-scroll`, 시트는 `.sheet-body`로 스크롤 소유권을 유지한다.

완료: 360/390/430px, 600px, 1280×600, 200% 확대에서 마지막 콘텐츠와 하단 메뉴에 도달 가능하며 이중 세로 스크롤·가로 넘침이 없다.

### UX-03 · P1 · 실패 안내가 없거나 열린 시트 뒤에 표시됨 — 코드 + 일부 재현

근거: `today/page.tsx:55,69,169,282`, `components/publish-sheet.tsx`, `components/explore-feed.tsx`, `lib/api.ts`, 각 댓글·채팅·설정 mutation. 경로의 `today/page.tsx`는 `apps/web/app/(product)/today/page.tsx`다.

TODO 생성·수정·게시 실패는 부모 화면의 notice에만 들어간다. 열린 시트에서는 배경이 가려지고 inert이므로 안내를 확인하기 어렵다. PublishSheet의 try/catch는 업로드는 잡지만 `void` 콜백으로 시작한 게시 mutation의 비동기 실패는 받지 않는다. 응원·댓글·채팅 반응 등에도 오류 표시가 없는 경로가 있다.

운영자 권한이 없는 체험 계정으로 `/admin/reports`를 열면 ‘운영자만 …’ 아래에 ‘연결을 확인하고 다시 시도해주세요’가 함께 표시됐다. 권한 문제에 네트워크 해결법을 제시한다.

수정: 상태 코드·안전한 오류 코드·입력 오류를 구분하는 프론트 오류 모델을 사용한다. 활성 시트 안에 오류와 재시도를 표시하고, 필요 시 필드와 `aria-describedby`로 연결한다. 401/403/404/409/429/5xx/오프라인을 구별한다. 서버 원문 `Internal server error`를 그대로 노출하지 않는다. 낙관적 원복과 사용자 안내를 함께 제공한다.

완료: 실패 주입 시 같은 화면에서 원인·다음 행동을 알 수 있고, 입력값은 유지되며 재시도로 정상 완료된다. 이미 진행 중인 인증/보안 수정과 충돌하지 않아야 한다.

### UX-04 · P1 · 가져오기 반복 정책 전환이 편집 내용을 초기화함 — 재현

근거: `apps/web/app/(product)/todos/import/page.tsx:78–88`.

재현: `/todos/import?postId=demo-post-routine` → ‘항목별 설정’ → TODO 이름 변경 → ‘원본 유지’ → 다시 ‘항목별 설정’. 제목이 원본 ‘3분 깊게 호흡하기’로 돌아왔다. 저장하지 않은 변경이 경고 없이 사라졌다.

수정: 원본과 사용자의 항목별 초안을 분리한다. 모드 전환만으로 초안을 재생성하지 않는다. 원본으로 초기화는 명시적인 행동으로 제공한다. 공통 날짜·시간 변경이 개별 설정에 미치는 범위도 설명한다.

완료: 제목·시간·반복을 편집한 뒤 모드를 왕복해도 보존된다. 실제 저장 payload와 완료 후 이동 날짜가 화면의 적용 결과와 일치한다.

### UX-05 · P1 · 그룹 조회 지연/실패가 ‘그룹 없음’ 저장으로 이어질 위험 — 코드

근거: `apps/web/components/todo-composer.tsx:25,61,78`, `today/page.tsx:282–283` 및 TODO 화면의 같은 호출부.

현재 그룹은 전달된 리스트에서 역산하고 `useState` 최초값으로 저장한다. 호출부는 조회 중/실패에도 `[]`를 넘긴다. 기존 그룹이 아직 확인되지 않은 상태에서 편집하면 ‘그룹 없음’으로 초기화되고 저장 시 `todoListId:null`을 보낼 수 있다. 카테고리 역시 조회 상태와 기본 옵션 표시를 구별하지 않는다.

수정: ‘아직 모름’, ‘조회 실패’, ‘명시적으로 그룹 없음’을 분리한다. 기존 관계가 확인되기 전에는 관계 변경을 보내지 않거나 안전하게 저장을 제한한다. 늦게 도착한 데이터를 반영할 때 사용자의 편집값을 덮지 않는다. 숨김/삭제된 카테고리는 기존 값과 상태를 명확히 표시한다.

완료: 그룹·카테고리 요청을 느리게 하거나 실패시킨 상태에서 제목만 수정해도 기존 관계가 유지된다. 실제 API 계약상 필드 생략과 null의 차이를 확인한 테스트가 필요하다.

### UX-06 · P1 · 피드 행동의 접근성 이름과 상태 누락 — 재현

근거: `apps/web/components/feed-card.tsx:14–17`.

접근성 트리에서 응원 버튼은 ‘84’, 댓글 링크는 ‘5’와 같이 숫자만 표시됐다. 사진이 있는 프로필 링크는 이미지의 빈 alt와 별도 이름 부재로 이름이 없었다. 응원 여부도 `aria-pressed`가 없다.

수정: ‘윤슬님의 프로필’, ‘응원하기, 84개’, ‘댓글 5개 보기’처럼 맥락 있는 이름과 선택 상태를 제공한다. 화면에 같은 문구를 중복해서 늘릴 필요는 없다.

완료: 피드·검색 결과·게시물 상세에서 아이콘만 보지 않아도 각 행동과 현재 상태를 구분할 수 있다.

### UX-07 · P1 · 터치 영역과 실제 공통 버튼 스타일 누락 — 재현 + 코드

측정: 360px 날짜 달력의 날짜 버튼은 40×44px, 채팅 메시지 메뉴는 36×36px, 반응 칩은 약 40.6×34px, 답장/반응 행동은 높이 40px이었다. 피드 이미지 프로필 링크는 42×42px이었다.

근거: `globals.css:150,433,437–438`, `components/todo-form-controls.tsx`, `components/feed-card.tsx`.

추가로 `challenges/[id]/page.tsx:64`의 사진 검수 진입 버튼은 `secondary-button full`을 쓰지만 검토 당시 `globals.css`에 `.secondary-button` 정의가 없었다. 실제 적용 스타일과 공통 버튼 연결을 확인해야 한다.

수정: 보이는 아이콘을 크게 만들기보다 겹치지 않는 히트 영역을 확보한다. 달력은 360px의 패딩·간격까지 계산해 7열을 유지한다. 누락된 버튼은 기존 보조 버튼 컴포넌트/토큰으로 통합한다.

완료: 프로젝트 계약인 최소 44×44px을 만족하면서 화면 밀도를 불필요하게 키우지 않는다. 참고로 WCAG 2.2 AA의 Target Size Minimum은 24×24px 또는 예외 조건이다. **44px은 이 프로젝트의 더 엄격한 기준**이며 모든 44px 미만 요소를 곧바로 WCAG AA 위반이라 부르면 안 된다. [W3C 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### UX-08 · P2 · 커스텀 입력과 검색 탭의 키보드 계약 미완성 — 재현 + 코드

근거: `components/todo-form-controls.tsx`, `components/sheet.tsx`, `components/todo-composer.tsx`, `app/(product)/explore/search/page.tsx:86`.

- 날짜를 선택해 패널이 닫히자 포커스가 BODY로 이동했다. 다음 Tab은 카테고리로 이동했다. 시트 밖으로 탈출한 것은 아니지만 날짜 트리거로 돌아오지 않았다.
- 시간 listbox에 다수의 옵션이 모두 Tab 대상이다. 선택된 시간으로 초기 스크롤/포커스를 맞추는 처리와 일관된 이동 규칙이 부족하다.
- 검색은 tablist/tab 역할을 쓰지만 tabpanel 연결·roving tabindex·방향키 처리가 없다.
- 반복 편집 범위와 일부 관심사 선택은 시각 클래스에만 선택 상태가 있다.

수정: 날짜·시간·생년월일·탭·선택 타일을 같은 접근성 원칙으로 정리한다. 패널 닫힘 후 트리거 복귀, 실제로 보이는 요소만 대상인 포커스 트랩, 단일 진입점의 옵션 탐색, 선택 표시를 구현한다. 단순 필터 버튼으로 유지할 영역은 불완전한 탭 역할 대신 `aria-pressed`를 사용한다.

수정: 안전한 내부 returnTo와 필터 URL을 전달한다. 히스토리로 복귀하되 직접 진입에는 명확한 fallback을 둔다. 외부 URL이나 인증용 비밀 값을 returnTo에 수용하지 않는다. 라우트별 제목과 실패/없는 페이지의 다음 행동도 정리한다.

완료: 비회원 가져오기 → 로그인/가입 → 원래 가져오기, 필터 피드 → 검색 → 뒤로, 새로고침/직접 링크가 맥락을 보존한다. 인증 보안 변경과 조정하면서 구현한다.

### UX-20 · P2/P3 · 이미지·CSS·회귀 테스트의 유지보수 기반 — 코드 + 제안

피드 이미지 등에 `unoptimized` 사용이 많다. 서버 썸네일·실제 이미지 크기·인증 URL 조건을 확인하고 반응형 전달/지연 로딩/실패 대체 화면을 설계한다. 이번에는 LCP 수치를 측정하지 않았으므로 ‘느림’으로 확정하지 않는다.

CSS는 여러 단계의 덮어쓰기와 매우 긴 압축 선언이 혼재한다. 이번 수정에 필요한 공통 토큰·컴포넌트부터 정리하고, 전역 CSS를 통째로 다시 쓰거나 끝에 또 덮어쓰기를 쌓지 않는다.

기존 문자열 기반 계약 테스트에 실제 마운트된 컴포넌트 테스트와 브라우저 회귀 시나리오를 추가한다. 시트 잠금·모드 전환 데이터 유실처럼 소스에 특정 단어가 있어도 발생하는 결함을 검출해야 한다.

완료: 프로덕션 빌드로 성능·초기 번들·이미지 전송량을 측정하고 환경을 기록한다. 목표 LCP≤2.5초, CLS≤0.1은 목표와 실측을 분리해 보고한다.

## 5. 유지할 디자인과 구체적인 정리 방향

1. 크림 배경·남색 본문·파스텔 포인트와 최대 430px 프레임을 유지한다. 장식 구름·유리 효과·새로운 대시보드형 디자인은 추가하지 않는다.
2. 일반 목록은 중립 면을 기본으로, 파스텔 면은 선택·카테고리·진행 상태에 사용한다. 모든 카드에 강한 그림자와 큰 모서리를 반복하지 않는다.
3. 큰 제목/설명/상태 카드가 연속되는 화면은 보조 설명을 접거나 한 줄로 줄인다. 첫 주요 행동과 실제 데이터가 먼저 보이게 한다.
4. 버튼을 줄이는 것과 터치 영역을 줄이는 것을 구분한다. 작은 아이콘 + 충분한 클릭 영역으로 밀도를 개선한다.
5. 카테고리는 갤러리, 일정은 펼친 목록과 얇은 그룹 경계, 그룹 구성은 별도 관리라는 확정 방향을 보존한다.
6. ‘게시’와 외부 ‘공유’를 구분한다. ‘루틴/반복/그룹’은 서로의 의미를 정한 뒤 화면별 용어표를 작성한다.
7. 오류는 사용자가 행동한 바로 그 위치에, 성공은 다음 행동을 방해하지 않는 위치에 보여준다.
8. 모션은 기존 토큰·축소 모션을 지킨다. 이번 작업에 새로운 애니메이션 연출은 필요하지 않다.

## 7. 회귀 검증 체크리스트

- 시트: 단일/중첩, 긴 본문, 360px, Esc/배경/닫기, focus return, 최상위만 활성, 잠금 잔류 없음.
- 입력: 날짜·시간 선택 복귀, 키보드만 사용, 5분 시간 규칙, 카테고리/그룹 지연·실패, 복합 반복 원본 보존.
- 초안: 가져오기 모드 왕복, 제출 지연, 사진 일부 실패, 업로드 완료 후 게시 실패, 재시도, 닫기/이탈.
- 핵심 순환: TODO 생성→완료→게시→다른 계정 응원/댓글→가져오기→완료.
- 검색: 일반/@사용자/#태그, 결과 종류, 빈 결과, 이전 URL, 필터 복원, 다음 페이지.
- 채팅: 두 방 이동, 바닥/과거 위치, 폴링/소켓 복구, 중복 이벤트, 읽음 배지, 사진/답장/삭제 메뉴.
- 상태: 초기 인증 복구·로딩·빈 결과·권한 없음·없어진 데이터·오프라인·401/403/409/429/500.
- 데이터 밀도: 긴 한국어/영문/공백 없는 텍스트, 큰 글자, 많은 해시태그, 100개 TODO, 반복 60일, 많은 그룹/카테고리.
- 화면: 360/390/430px, PC 중앙 프레임, 낮은 창, 200% 확대, 실제 모바일 키보드, safe area.
- 접근성: 한국어 이름·선택 상태·오류 연결·포커스·키보드·대비·동적 안내·축소 모션.
- 검증 명령: 웹 단위/브라우저 테스트 → `npm run lint` → `npm test` → `npm run build`. 운영 의존성 감사는 기존 배포 점검과 함께 수행한다.

실행 불가능한 검증은 이유와 필요한 환경을 남긴다. ‘미실행’을 ‘통과’로 바꾸지 않는다.
