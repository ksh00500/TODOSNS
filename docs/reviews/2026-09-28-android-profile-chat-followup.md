# Android 마이·채팅 후속 구현 기록

작성일: 2026-09-28. 기존 웹 API·패키지·서명·minSdk 24와 미커밋 변경을 유지했다. 사용자 요청에 따라 배포가 필요한 실제 Play Google 확인은 보류하고 독립적인 로컬 구현을 진행했다.

## 구현 내용

- 마이: 웹 기준 프로필·게시물/팔로워/팔로잉 수, 성장 진행, 완료/응원/가져가기 통계, 그룹 3개와 최근 게시물 6개, 기본·챌린지 배지와 발행자/조건/관련 챌린지 시트를 추가했다. 큰 글꼴에서는 통계·게시물·배지를 한 열로 배치한다.
- 프로필 데이터: 명시 모델·Repository·ViewModel·불변 StateFlow를 사용한다. 필수 수치 누락을 0으로 숨기지 않으며 그룹/게시물 조회 실패를 빈 기록과 구분한다. 그룹 미조회·실패 동안 루틴 배지는 미확인으로 표시한다. 섹션 재시도와 요청 세대로 늦은 응답을 막는다.
- 채팅: 안정적인 첨부 키로 최대 4장을 관리한다. 한 장 제외 뒤 늦은 업로드 응답이 해당 슬롯을 복원하지 않는다. 업로드 중·실패한 첨부는 전송을 막고 제외·재시도를 제공한다. 저장 상태 복원과 전송 실패 후 이미 성공한 미디어 ID/본문/요청 키를 유지한다. 받은 사진은 썸네일과 원본 비율 보기를 구분한다.
- 링크: 서버의 http/https 링크만 사용자의 클릭으로 열며 외부 미리보기를 조회하지 않는다. javascript/intent 주소는 표시·실행하지 않는다. 외부 열기 실패는 화면에 알린다.
- 챌린지: 작성·편집·목록 날짜에 계정 시간대를 전달했다. Los Angeles 계정의 전날 표시와, 날짜를 바꾸지 않은 편집이 기존 시작/종료 일시를 보내지 않는 것을 검사한다.
- Google: provider 취소·결과 없음·시간 초과를 구분한다. 실패 시 앱 버전·단계·허용된 HTTP 상태의 확인 시트를 제공한다. ID 토큰·개인정보를 저장 상태나 로그에 남기지 않는다. 실제 기존 계정 무반응의 원인/해결 여부는 여전히 미확정이다.

주요 소스는 `apps/android/app/src/main/java/kr/kro/mungsil/data/ProfileRepository.kt`, `ui/ProfileModel.kt`, `ui/ProfileScreen.kt`, `ui/ChatPhotos.kt`, `ui/ChatScreen.kt`, `ui/GoogleLoginModel.kt`이다. 테스트 주소·사진 선택 대체 구현·공유 합성 데이터는 테스트에만 둔다.

초기 연결 검사에서는 사진 노드를 찾지 못해 27/28만 통과했다. 인터넷을 끈 에뮬레이터에서 Coil의 연결 감지가 loopback 이미지 요청도 차단하는 테스트 환경 문제를 확인했다. 테스트용 이미지 로더만 연결 감지를 끄고 localhost/127.0.0.1 이외 요청은 거부하도록 바꾼 뒤 해당 검사 1/1이 통과했다. 제품 이미지 로더의 연결 정책은 변경하지 않았다. 근거는 [Coil 2.7.0 ImageLoader 소스](https://github.com/coil-kt/coil/blob/2.7.0/coil-base/src/main/java/coil/ImageLoader.kt)다.

시트 캡처에서 여러 Compose root 선택 실패와 별도 창의 배경 캡처를 발견했다. 시트 제목을 확인한 후 프레임을 기다리고 시스템의 합성 화면을 캡처하도록 테스트 도구를 수정했다. 동작 성공만으로 잘못 캡처된 이미지를 화면 일치 증거로 취급하지 않는다.

캡처 도구 최종 수정 후 마이 저높이·마이 글꼴 200%·채팅 원본 보기 3건을 다시 실행해 모두 통과했다. 배지 제목/발행자/조건, 긴 프로필 줄바꿈, 1:2 원본 사진 표시가 실제 캡처에 있는 것을 확인했다. 비교 보고서의 채팅 원본 이미지는 같은 360dp 합성 시나리오의 이 최종 캡처를 그대로 사용한다.

## 증거와 제한

결과 로그·원본 이미지는 `outputs/android/native-verification/`, 웹 이미지는 `outputs/android/web-parity/`, 비교 보고서는 `outputs/android/parity-comparison.html`에 둔다. 5/28(약 18%)은 공유 캡처 확보율이며 전체 시각 동등성 통과율이 아니다. 마이 첫 화면·긴 소개·빈 기록·배지 시트와 사진 보기만으로 모든 부속 시트까지 완료 처리하지 않는다.

전체 진행률은 약 55% 작업량 추정이다. 남은 관리 항목 중 D1·D2·F1의 구현/로컬 검증 3/36을 끝냈으며 이는 모든 기능의 외부 검증 완료를 뜻하지 않는다. E1의 계정 시간대와 H의 프로필 구조·복구는 부분 완료이고 해당 항목 전체 체크는 남긴다. 세 화면 폭의 마이 첫 화면과 긴 문구에서 가로 잘림을 발견하지 않았으나 아이콘·여백·장식 차이와 23개 미캡처 화면은 계속 대조한다.

기기 검사는 API 36.1 에뮬레이터와 loopback MockWebServer를 사용한다. 사진 선택 대체 구현은 첨부 상태·실패 재시도·저장 상태 복원을 검사할 뿐 실제 OS 사진 선택·촬영·스토리지 업로드를 증명하지 않는다. StateRestorationTester는 실제 프로세스 종료 검사가 아니다.

실제 Play Google/FCM, API 24·실기기 키보드/TalkBack/회전/프로세스 종료, 격리 DB·스토리지·소켓·두 계정 순환은 미실행으로 유지한다. OAuth/서버 Google 설정을 재확인하지 않았고 실제 기존 계정 로그인 성공으로 표시하지 않는다.

서버 코드 변경·서버 접속·배포·Play 업로드·새 AAB 제작은 이번 작업에서 수행하지 않았다. 기존 Firebase 관리자 키·서명 키를 재생성하거나 앱에 넣지 않았다. 다음 작업은 공개 프로필·관계, 핵심 TODO/그룹/가져오기 세부 상태와 나머지 화면 대조이며 실제 설치본 확인은 배포가 가능해진 뒤 별도로 재개한다.
