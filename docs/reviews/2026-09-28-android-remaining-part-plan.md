# Android 웹 동등성 — 남은 작업과 파트별 진행 계획

작성일: 2026-09-28. 기준: 현재 웹 일반 사용자 화면, 디자인 시스템, Android 코드와 검증 기록. 관리자 센터와 새 제품 기능은 범위에서 제외한다.

## 진행률의 의미

아래 초기 수치는 마이·채팅 후속 구현 전 기준이다. 챌린지 인증·검수 후속 구현 이후 추정치는 약 64%이며 실제 설치본 확인은 사용자 요청으로 보류한다. 최신 결과는 [챌린지 후속 기록](2026-09-28-android-challenge-followup.md)과 [게시·검색 후속 기록](2026-09-28-android-publish-search-followup.md)을 참조한다.

기존에 보고한 약 50%는 구현·디자인 정합성·연동·기기 검증을 함께 고려한 작업량 추정이다. 기능 항목을 집계한 정확한 완료율이 아니며, 화면 절반이 없다는 의미도 아니다. 지금은 많은 화면과 API 연결이 있고, 세부 동작과 화면 구성의 차이 및 미검증 흐름이 남아 있다.

- Android 로컬 단위 검사 20/20, 최신 연결 검사 22/22, 화면 크기별 검사 7환경 합계 70건이 통과했다. 이 숫자는 해당 테스트 범위의 결과다.
- 웹·앱 공유 데이터 비교 캡처는 일반 사용자 화면 28개 중 4개(약 14%)다. 이 4개에도 카드 크기·시간 표현·피드 대체 기록·상세 행동 배치의 차이가 남아 있다. 캡처 확보율을 시각 동등성 통과율로 취급하지 않는다.
- 실제 Play 설치본 Google 로그인·FCM, API 24, 격리 DB·스토리지·실제 소켓 통합 검증은 완료되지 않았다.
- 기존 1.2.0(5) 서명 AAB는 로컬 내부 테스트 산출물이며 전체 전환 완료의 증거가 아니다.

근거: [28개 화면 추적표](2026-09-28-android-parity-validation.md), [구현·검증 기록](2026-09-24-android-web-parity.md). 아래 미완료 체크리스트는 남은 작업의 관리 기준이며 이미 완료된 기능을 미구현으로 다시 분류하지 않는다.

## 1. 로그인·가입·이메일 링크 — 최우선

2026-09-28 사용자 지시에 따라 배포가 필요한 실제 Play 설치본 확인은 보류한다. A1~A3의 실제 계정 검사를 완료로 처리하지 않으며, 로컬 구현과 합성 검사는 계속 진행한다.

현재: 자체 세션, Google 단계별 오류와 시간 초과, 결과 없음·취소 안내, 신규 추가 정보, 이메일 인증·비밀번호 재설정 화면은 있다. 합성 provider 검사는 통과했다. 기존 실제 계정 선택 후 창만 닫히는 문제의 원인과 해결 여부는 미확정이다.

- [ ] A1. 실제 Play 설치본에서 기존 계정 선택 → 자격 증명 결과 → ID 토큰 획득 → 서버 세션 교환 → 내 정보 → 화면 복귀의 어느 단계가 중단되는지 확인하고 해당 결함을 수정한다. 단계·오류 코드·요청 ID만 기록한다.
- [ ] A2. 실제 설치 서명과 Android OAuth, 앱이 요청하는 웹 클라이언트 ID와 서버 허용 설정을 대조한다. 업로드/debug 지문과 Play 서명을 구분하고 키를 재생성하지 않는다.
- [ ] A3. 기존/신규 Google 계정, 취소·충돌·만료·네트워크 실패·앱 재실행·계정 전환의 결과와 로그인 후 원래 화면 복귀를 검증한다. 실제 계정 검사와 합성 검사를 따로 기록한다.
- [ ] A4. 이메일 인증·재전송·비밀번호 재설정·온보딩을 격리 계정과 실제 Android 링크 진입으로 끝까지 검사한다. 정상/만료/중복 링크와 앱 실행 전후를 포함한다.

완료 기준: 기존 계정 선택 후 로그인과 화면 이동이 성공하고, 실패·취소는 사용자가 이해할 수 있게 표시된다. 신규 가입과 이메일 링크도 세션·온보딩·복귀가 맞는다. 토큰은 로그·저장 상태에 남기지 않는다.

환경: 로컬 합성 검사는 즉시 가능하다. 실제 Google는 내부 테스트 설치와 기기, OAuth 설정 확인이 필요하다. 실제 이메일은 격리 메일/서버 환경이 필요하다. 실패 원인 확인 전에는 서버 문제나 서명 문제로 단정하지 않는다.

## 2. 공통 UI·랜딩·탭·뒤로 가기

현재: 공통 폰트·색상·시트, 명시적 탐색 경로, 탭 복원, 저높이·큰 글꼴 대응을 일부 구축했다. 랜딩은 문구와 기본 소개 카드 중심이고 웹의 전체 미리보기 구성이 부족하다.

- [ ] B1. 랜딩의 제품 미리보기, 오늘의 진행 카드·시간 표현, 피드 카드와 게시물 상세의 제목·가져오기·보조 행동 배치를 웹 기준으로 완성한다.
- [ ] B2. 각 파트 작업과 함께 전체 28개 화면 및 주요 시트를 같은 합성 데이터로 캡처한다. 정보 순서·문구·주 행동·사진 비율·빈 상태·오류 차이를 남기고 해결한다.
- [ ] B3. 탭별 날짜·필터·스크롤, 중첩 상세 뒤로 가기, 로그인 후 목적지, 시트 종료·복귀를 검증한다. 회전과 프로세스 종료도 별도 시나리오로 검사한다.
- [ ] B4. 360/390/430dp·저높이·글꼴 200%에서 터치 영역·키보드·포커스·TalkBack·스크롤 소유권을 화면별로 확인한다.

완료 기준: 제품 화면의 정보와 행동이 웹과 대응되고, 상세를 다녀와도 이전 위치가 유지된다. OS 계정/권한/사진 선택 UI 차이는 허용한다.

## 3. TODO·그룹·카테고리·게시·탐색·가져오기

현재: 핵심 API 연결과 합성 TODO 생성→완료→게시, 응원/댓글 실패 복원, 카테고리 편집, 루틴 간격·복잡한 반복 보존은 구현 및 일부 검증했다. 모든 반복 범위와 실제 두 계정 순환은 미검증이다.

후속 구현: C1은 정확한 원본 일시·복잡한 반복·THIS/FUTURE 요청 계약·단일 삭제/복원 재시도/반복 종료·그룹 검색/커서/복원 뒤 선택·공개 범위 보존을 단위/합성 화면 검사했다. C2는 갤러리·보관·키보드/접근성 정렬·카테고리 페이지→날짜 이동과 그룹 생성/게시/삭제 계약을 보완했다. C3는 게시 사진 초안·태그 확정/삭제·공개 범위·복원/재시도 키, 검색 전체 유형·최근 검색·오류/빈 상태·늦은 응답과 공유 캡처를 추가했다. 실제 PhotoPicker 파일 읽기·presign 실패·제외를 확인했으나 OS 선택기·S3 성공은 별도다. 각 항목의 전체 상태·시각·실기기·실제 DB 판정은 남아 있어 상위 체크를 일괄 완료하지 않는다.

- [ ] C1. 단일/시리즈 반복 편집, 삭제·복원·반복 종료, 일정 날짜 전체 목록을 검증하고 누락을 보완한다. 그룹 검색·추가 조회 중 선택 유지와 공개 범위 보존도 실패까지 검사한다.
- [ ] C2. 그룹 생성·구성·게시와 카테고리 갤러리·숨김·정렬·소속 목록의 전체 사용 흐름을 완성·검증한다. 정렬의 접근성 조작을 포함한다.
- [ ] C3. 게시 사진·본문·태그·공개 범위, 댓글 페이지, 검색의 모든 결과 유형·최근 검색, 단일/루틴 가져오기 항목 편집을 웹과 대조한다. 업로드 재시도/제외와 초안·반복·상대 일정 보존을 검사한다.
- [ ] C4. 격리된 두 계정으로 웹과 앱을 번갈아 TODO 생성 → 완료 → 게시 → 응원·댓글 → 가져오기 → 다시 완료를 실행하고 DB 결과를 확인한다. 중간 실패·재시도를 포함한다.

완료 기준: 원본 반복·일정·공개 범위가 의도 없이 바뀌지 않고, 실패 후 입력과 재시도 상태가 유지된다. 핵심 순환이 실제 HTTP·DB에서 양쪽 클라이언트로 통과한다.

## 4. 마이·공개 프로필·관계·등급

현재: 프로필 편집·사진·관심사, 팔로우·차단·신고·등급 화면은 있다. 내 게시물/그룹 미리보기, 가져가기 수치, 기본/챌린지 배지와 조건 시트를 추가했다. D1·D2·D3의 로컬 보완과 검사 결과는 후속 기록에 남겼으며 D4의 실제 두 계정 관계 전이·전체 시각 대조는 미완료다.

- [x] D1. **구현·로컬 검증 완료:** 웹 마이의 프로필 카드, 게시물 수, 성장 진행, 가져가기 활동 수치, 내 게시물·그룹 미리보기를 기존 API로 구성한다. 실제 사진·전체 시각 판정은 B/I의 후속 검사다.
- [x] D2. **구현·로컬 검증 완료:** 웹의 기본 배지 조건과 챌린지 획득 배지를 같은 흐름으로 표시하고, 등급별 경계값·최고 등급·진행률·조건 설명을 대조한다. 등급 상세 전체 시각 판정은 B/I에 남긴다.
- [x] D3. **구현·로컬 검증 완료:** 공개 프로필의 수치·소개·등급·실천 행동과 팔로워/팔로잉의 사진·아이디·등급·방향 선택을 구성했다. 페이지 실패·재시도·중복 제거, 접근 불가 사용자 링크 차단, 본인/타인 행동, 권한 상실 후 이전 기록 제거를 합성 검사했다. 전체 시각 일치/실제 관계 DB 판정은 B/I/D4에 남긴다.
- [ ] D4. 두 계정의 팔로우→대화 요청→차단→해제를 검증한다. 해제 시 관계나 기록을 자동 복원/삭제하지 않고 관련 화면을 재조회하는지 확인한다.

완료 기준: 웹에서 볼 수 있는 사용자 기록과 기존 배지 조건이 앱에도 있고, 관계 변경 결과가 프로필·피드·대화에 일관되게 반영된다.

## 5. 챌린지·인증·검수·결과

현재: 개설·편집·참여·체크/사진 인증·기준별 검수·성공률·순위·보상 정보는 부분 구현됐다. 작성·편집·목록 날짜에 계정 시간대를 적용하고 기존 일시 보존을 검사했다. 추가로 사진 미완료/복원·재인증 필수 사진·저장 중 제한·제출 키·기준별 검수 복원·사진 실패/확대/신고를 보완했다. 서버에는 종료/기간/멤버십 검사와 대기열 제한을 추가하고 웹 재인증 버튼 조건도 맞췄다. E1의 전체 화면 대조·E2 실제 DB·E3 실제 다계정 업로드·E4 실제 HTTP/DB·채팅 검사는 여전히 남는다.

- [ ] E1. 생성·편집·상세·결과를 웹과 대조하고 계정 시간대에 맞춘 날짜 입력을 적용한다. 기존 일시와 서버가 관리하는 보상 필드를 보존한다.
- [ ] E2. 개설 포인트·최소 참여 조건·진행률·순위·칭호·보상을 실제 격리 DB 결과와 대조한다. 부족 포인트·중복 제출·기간 경계를 검사한다.
- [ ] E3. 여러 계정으로 사진 제출→기준별 검수→반려→사유 확인→재인증을 검사한다. 업로드 실패·판정 실패·재시도·가능 기간도 포함한다.
- [ ] E4. 작성자 편집·종료·삭제, 참여 취소·탈퇴, 종료 이후 변경 거부와 채팅 제한의 화면/서버 결과를 검사한다.

완료 기준: 역할·기간·포인트·인증 상태에 따라 웹과 같은 행동이 허용되고, 반려와 종료 뒤의 후속 흐름까지 통과한다.

## 6. 대화함·1:1·챌린지 채팅

현재: 요청·수락/거절, 통합 대화 목록, 답장·반응·삭제·챌린지 수정/설정, 단절 시 조회 복구와 차단 기록 보존이 있다. 이번 후속 작업에서 최대 4장 첨부·제외·실패 재시도·저장 상태 복원·원본 비율 보기와 http/https 링크 카드를 추가했다. 실제 OS 사진 선택·스토리지 업로드와 F2~F4 검사는 남아 있다.

- [x] F1. **구현·로컬 검증 완료:** 웹 기준의 복수 사진 첨부·미리보기·제외·재시도·확대 보기와 허용 링크 카드를 완성한다. 업로드 미완료 상태에는 전송을 막는다. 실제 OS 사진 선택·촬영·스토리지 업로드는 I의 외부 검증에 남긴다.
- [ ] F2. 대화 목록·요청 시트·말풍선·사진 배열·답장·날짜·읽음 표시를 웹/API 계약과 대조한다. API에 없는 상대 읽음 기능을 임의로 추가하지 않는다.
- [ ] F3. 실제 소켓 연결 단절/재연결, 방 재참여+즉시 조회, 중복 이벤트·정렬·추가 조회·과거 위치 유지·초안을 격리 환경에서 검사한다.

완료 기준: 메시지 누락·중복·강제 스크롤·초안 손실이 없고, 복수 첨부와 권한 변화가 웹의 기존 정책과 일치한다.

## 7. 알림·푸시·설정·약관·외부 연결

현재: 알림 목록·명시적 읽음, 대상 권한 재확인, FCM 등록/해제와 권한 UI, 로그아웃·전체 로그아웃·탈퇴·공유 약관 원문은 있다. 실제 FCM와 OS/기기 전환은 미검증이다.

- [ ] G1. 모두 읽음 처리 중 새 알림, 개별 읽음 실패, 읽지 않은 수 재조회와 채팅 읽음 분리를 검사한다. 진입·푸시 탭으로 자동 읽지 않는 정책을 유지한다.
- [ ] G2. 실제 기기에서 푸시 권한 거부/허용, 전경/백그라운드·앱 종료, 계정 전환·로그아웃, 대상 권한 상실과 로그인 복귀를 확인한다. 실제 발송은 지정된 테스트 계정에 한정한다.
- [ ] G3. 게시물·프로필·챌린지·이메일 App Links와 외부 공유를 검사하고, 허용 도메인/경로만 처리한다. 링크 목적지는 로그인 과정에서 보존한다.
- [ ] G4. 모든 기기 로그아웃·탈퇴의 성공/실패·확인 흐름과 약관 긴 문서·글꼴 200%를 검사한다. Firebase 관리자 키는 서버에만 둔다.

완료 기준: 알림/푸시가 현재 계정의 접근 가능한 화면으로 이동하고 읽음 정책을 지킨다. 계정 종료 후 세션·기기 연결이 정리된다.

## 8. 상태 관리·Repository·복구 구조 — 각 파트와 함께 진행

현재: Google·TODO·마이·공개 프로필·검색·사진 검수에 ViewModel/명시 모델을 적용했으며 다른 화면에는 JSON 중심 조회·화면 상태 처리가 남아 있다. 필수 응답 누락·지연 응답·섹션별 재시도·복원/제출 키는 각 변경 범위에서 검사했다. 일괄 구조 변경으로 기능 작업을 멈추지 않고 각 파트의 변경 범위 안에서 정리한다.

- [ ] H3. 늦은 응답·중복 제출·계정 전환·조회 취소·낙관적 실패 복원·요청 키 재사용을 해당 파트 테스트로 확인한다.

완료 기준: 변경 대상 화면의 비동기 상태와 복구가 예측 가능하고, 지연 응답으로 목록 갱신이 빠지지 않는다. 타입 전환 자체만으로 기능 완료를 판정하지 않는다.

## 진행 순서와 작업 단위

현재 실행 순서는 사용자 지시에 따라 **Google 실제 계정 확인을 보류하고 E1의 목록/결과 구성 → G의 알림·계정 종료 → B의 남은 화면 대조**다. C1/C2/C3/D3와 E의 인증/검수·기간/멤버십 로컬 보완은 후속 기록에 반영했다. C4/D4와 E의 실제 DB·다계정 검사 및 실제 Google·FCM 검사는 필요한 격리 환경이나 설치본이 준비된 뒤 실행하며, 그 전에도 독립적인 앱 수정을 진행한다.

1. **A 로그인 원인 확인 + B 공통 기준**: 실제 기존 계정의 무반응 원인을 먼저 추적한다. 외부 기기 확인을 기다리는 동안 B1의 게시물 상세/오늘 차이를 수정하고 D1·D2 마이 화면을 완성한다.
2. **C 핵심 순환 + D 프로필/관계**: 반복·그룹·게시·가져오기와 기록 표시를 화면 및 동작 단위로 마무리한다. 격리 두 계정 검사를 이 단계부터 실행한다.
3. **E 챌린지 + F 채팅**: 역할·기간·반려·재인증·종료, 복수 사진·실제 소켓 복구를 완성한다. 결과·권한 상태를 각각 캡처한다.
4. **G 알림/계정/링크**: 동시 읽음과 계정 전환, 실제 FCM·App Links·계정 종료를 마무리한다.
5. **I 최종 판정**: B2~B4의 전체 화면 증거와 H의 구조/복구 체크를 모아 API 24/36 및 실기기까지 검사한 뒤 출시 후보를 확정한다.

H는 1~4번에서 해당 기능과 함께 적용한다. 실제 Google·FCM·통합 환경 검사는 마지막에 처음 시도하지 않고 준비되는 즉시 실행한다. 외부 검사가 대기 중이면 독립적인 로컬 수정은 계속 진행한다.

## 이후 진행률 보고 방법

이 문서에는 남은 작업 관리 항목 36개가 있다. 각각 여러 행동을 포함하므로 동일한 작업량으로 간주하지 않는다. 이를 원래 전체 계획의 나머지 50%와 산술적으로 합산하지 않는다.

후속 구현 기준 D1·D2·D3·F1의 구현/로컬 검증 4/36을 완료했다. C1/C2/C3/H의 여러 하위 행동도 추가했지만 상위 항목의 남은 범위를 이유로 체크는 유지한다. 체크 표시는 명시된 로컬 범위의 완료이며 모든 실기기·외부 검증을 통과했다는 뜻이 아니다.

- 파트 상태는 `미착수 / 구현 중 / 로컬 검증 완료 / 외부 검증 대기 / 완료`로 기록한다. 구체적으로 어느 하위 항목이 끝났는지 함께 보고한다.
- 수치 보고는 분모를 명시한다: `남은 관리 항목 완료 n/36`, `비교 캡처 확보 n/28`, `시각 대조 통과 n/28`, `실행한 필수 검증 통과 n/m`.
- 합성 Google와 실제 Play Google, 합성 HTTP와 실제 격리 DB·스토리지·소켓 결과를 분리한다. 단계 작업 100%를 전체 프로젝트 100%로 표현하지 않는다.
- 전체 진행률은 현재 약 64% 추정임을 명시한다. 세부 행동 분해와 검증 증거가 쌓인 뒤 기준을 고정해 계산값으로 교체한다.

## 서버·배포 경계

최초 정리는 계획 문서 작업이었다. 이후 승인된 후속 구현에서는 앱 코드와 팔로우 서버 검사를 보완하고 로컬 검증을 진행했다. 팔로우의 활성 대상/양방향 차단 검사와 챌린지의 종료/기간/멤버십 검사·웹 버튼 조건은 별도 서버/웹 배포가 필요하다. 이번 챌린지 변경에는 새 migration이나 운영 설정 변경이 필요하지 않다. 새 AAB 빌드·운영 서버 접속·배포·Play 업로드는 수행하지 않았다. 근거는 [최신 후속 기록](2026-09-28-android-challenge-followup.md)에 남긴다.

앱 UI·탐색·상태 관리는 기본적으로 기존 API를 사용한다. 실제 계약 누락이 확인될 때만 웹/구버전 앱과 호환되는 서버 변경을 별도 제안한다. OAuth 설정 확인은 서버 코드 배포와 다른 작업이다. 준비된 `assetlinks.json` 서명 지문과 공유 약관 원문 변경은 웹 호스팅 반영 여부를 따로 확인해야 한다. 이전 DB·푸시 서버 배포 상태는 이번 로컬 기록만으로 재확인된 것으로 취급하지 않는다.

기존 패키지·서명 키·minSdk 24와 미커밋 변경을 유지한다. 실제 테스트에 필요한 기기·계정·격리 환경이 없으면 해당 항목은 대기로 기록하고 전체 완료 판정을 보류한다.
