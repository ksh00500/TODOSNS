# Android 챌린지 인증·검수 후속 구현

2026-09-28. Google 실제 계정 확인을 보류하고 E의 로컬 인증·검수·기간/역할 화면을 보완했다. 서버에서 종료 이후 재인증·검수의 기간 검사 누락도 확인해 Android·서버·웹 조건을 함께 수정했다. 운영 서버 접속·배포·Play 업로드·새 서명 AAB 제작은 하지 않았다. 이전 팔로우 서버 변경과 이번 챌린지 서버·웹 변경은 별도 배포가 필요하다.

## 수정한 동작

- `ChallengeCheckInSheet`를 분리해 사진→한마디 순서, 일반 인증/새 사진 재인증 제목과 제출 문구를 웹에 맞췄다. 새 사진 재인증은 항상 사진을 요구한다. 미완료 사진의 URI·미디어 ID·진행 상태를 폼에서 소유하고 복원 직후 제출을 막는다.
- 성공한 미디어 ID와 입력을 실패 후 유지하며, 같은 실패 제출에는 같은 요청 키를 사용한다. 한마디는 전송 시 앞뒤 공백만 제거한다. 저장 중 입력·사진 조작·닫기를 막는다. 실제 OS 사진 선택과 스토리지 성공은 별도 검사다.
- 개설/편집도 같은 제출 키를 저장 상태로 유지하고 저장 중 날짜·방식·기준·칭호·본문 입력을 막는다. 기존 시작/종료 일시와 서버 보상 필드를 보존한다. 500포인트 부족의 서버 응답은 초안을 보존하고 안내하지만 실제 포인트 차감은 이번 합성 검사로 증명하지 않는다.
- 검수는 `VerificationRepository`의 명시 모델과 `VerificationModel`의 불변 StateFlow·요청 세대를 사용한다. 잘못된 필수 배열·수치·기준을 빈 목록으로 숨기지 않는다. 조회 실패/실제 빈 목록/사진 실패를 구분한다.
- 사진은 잘리지 않는 비율로 표시하고 확대 보기와 인증 ID를 대상으로 한 신고를 제공한다. 사진 로딩 실패는 재시도할 수 있고, 사진이 확인되기 전에는 판정을 제출하지 못한다. 작성자나 투표 수는 보여주지 않는다.
- 기준별 판정의 단계·선택·실패한 제출 키를 복원한다. 인증 ID·시도 번호·확인 기준이 달라지면 이전 판정을 적용하지 않는다. 앞 단계로 돌아가 답을 바꾼 제출에는 새 키를 사용한다. 신고도 실패 입력·키를 유지하고 성공/취소를 구분한다.
- 상세 날짜는 계정 시간대로 표시한다. 시작 전·종료·잘못된 일정에는 참여/인증 행동을 구분하고, 재인증은 참여 상태·반려·시도 1~2·유효 기한을 확인한다. 조회 오류 중에는 이전 상세와 변경 행동을 표시하지 않는다. 인증 기록이 실제 비어 있을 때만 빈 상태를 표시한다.
- 서버는 수동 종료·기간 종료·시작 전·숨김 상태의 새 사진/같은 사진 재인증·검수 투표를 거부하고 대기열도 진행 중 챌린지만 조회한다. 재인증 요청의 현재 멤버십과 검수 요청의 제출자/검수자 멤버십을 다시 확인한다. 거부된 새 사진 요청은 미디어 첨부 전에 종료한다. 작성자/운영자의 종료 후 편집은 거부하고 시작 전 편집은 유지한다. 웹도 종료·시작 전·비참여 상태에 재인증/검수 버튼을 제공하지 않는다.

## 로컬 검사

단위 검사 54/54, 전체 연결 검사 49/49, Android lint(0 errors·32 warnings)·APK 빌드는 통과했다. 캡처에서 원본 확대가 작은 이미지의 실제 픽셀 크기로 표시되는 문제를 발견해 원본 비율로 화면 폭에 맞추고 실제 크기/비율 assertion을 추가했다. 최종 수정본은 360/390/430dp에서 신규 6개 검사씩, 저높이/글꼴 200% 6조건, 기존 챌린지 3개 회귀 검사를 합해 10조건·27회 통과했다. 네 조건의 인증/개설 검사는 캡처를 요청하지 않으며 스크린샷 없음 경고를 검사 실패로 간주하지 않는다. 기기 검사는 loopback HTTP·합성 사진과 테스트 선택기 콜백을 사용하고 에뮬레이터 Internet을 잠시 끈다. 복원은 `StateRestorationTester`이며 실제 프로세스 종료가 아니다.

서버 행동 검사 10개를 추가했다. 거부 상태에는 투표/미디어 첨부/인증 변경이 실행되지 않는지 확인하며, 진행 중인 정상 흐름과 시작 전 편집도 검사한다. 전체 `npm test`는 API 125 통과·4 skip, Web 53/53 통과다. 웹 브라우저는 360/390/430px에서 진행 중·수동 종료·기간 종료·시작 전·비참여 상태의 버튼 검사 3/3을 통과했다. 실제 DB 트랜잭션·동시 종료 경합은 이 합성 검사로 증명하지 않는다.

원시 로그는 `outputs/android/native-verification/challenge-*.log`, 조건별 `challenge*-tests.txt`, 캡처는 조건별 폴더에 남긴다. 전체 연결 원문은 `challenge-connected49.log`, 최종 행렬 수치와 검사 APK 해시는 `challenge-matrix-results.json`, 합계는 `2026-09-28-challenge-verification-summary.json`에 기록한다. 저장소 lint·API/Web 전체 빌드와 `git diff --check`도 통과했다. 게시·검색까지의 전체 연결 43/43 결과는 `publish-search-connected43.log`로 별도 보존했다. 비교 문서 `outputs/android/parity-comparison.html`에는 챌린지 상태 캡처를 부속 자료로 추가했다.

## 남은 범위와 경계

- E1 목록의 전체/주목/지난 챌린지 구성과 결과 화면 전체 시각 대조, 개설/편집 필드별 상태 검사는 아직 남는다. 이번 인증/검수 캡처는 공통 web fixture 비교 캡처 수에 합산하지 않는다.
- E2 실제 포인트·다계정 참여·진행률·순위·칭호·보상 DB 결과, E3 실제 업로드와 다계정 판정/반려/재인증, E4 기간·멤버십·종료 후 변경의 실제 HTTP/DB 검사와 실제 대화 제한은 미완료다.
- 서버·웹의 종료 후 변경 검사 누락은 로컬에서 보완했지만 배포하지 않았다. 새 migration이나 환경 설정은 필요하지 않다. 이전 DB/FCM 미커밋 변경과 실제 서버 반영 여부를 이 기록으로 재확인하지 않는다.
- 실제 Google·FCM·API 24·실기기 키보드/TalkBack·회전/프로세스 종료·격리 DB/스토리지/소켓은 대기다. 기존 1.2.0(5) AAB는 이번 로컬 변경을 포함하지 않는다.

전체 작업량 추정은 약 64%다. 기능 대조표의 모든 항목 통과율이나 출시 완료율로 사용하지 않는다.
