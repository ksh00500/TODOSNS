## 변경 절차

결정마다 일시·근거·영향 받는 요구/계약·재검토 조건을 기록한다. 제안을 사용자의 승인으로 표현하지 않는다. 과거 handoff 본문을 새 결정으로 덮어쓰지 않는다. 새 설계가 현행 AGENTS·디자인·개인정보 정책과 충돌하면 충돌과 변경 범위를 먼저 명시한다.

## V1 상세 설계 근거 · 2026-10-23

[Android V1](android-v1/README.md)에 화면·상태·API·검수 초안을 추가했다. 현행 완료 취소의 게시 연결 제한과 날짜/관계 보존을 유지하는 방향이며, 실제 완료일 기록은 추가 API 설계안이다. 사용자 승인·구현·실행 검증과 구분한다.

## 구현 선택 E-001 · 완료 기록 API · 2026-10-23 UTC

사용자의 후속 개발 진행 지시에 따라 M-04에 적용한 개발 기준이다. 별도의 사용자 확정 발언이나 운영 정책 승인으로 표현하지 않으며, 제품 검토 때 조정할 수 있다.

| 선택 | 이유·영향·재검토 조건 |
| --- | --- |
| 현재 완료 상태인 본인·미삭제 항목만 completedAt으로 조회 | 기존 TODO·권한·파기 정책 보존. 감사 이벤트 원장·삭제 원문 보관을 추가하지 않음 |
| 기본 최근 7개 현지 날짜, 최대 90일, 기본 20/최대 50개 | 기존 상세 초안의 제한을 개발 기본값으로 적용. 실제 사용성·운영 규모에 따라 조정 |
| 날짜 쌍 생략은 첫 페이지에만 허용 | 이후 페이지는 응답의 fromDate/toDate를 명시해 자정 후 기간이 이동하지 않게 함 |
| 서명 커서를 사용자·기간·canonical timezone·limit·필터 버전에 연결 | 위변조와 다른 조건 재사용 거부. 키 회전/조건 변경은 첫 페이지 재조회 |
| 목록·total·시간대를 RepeatableRead transaction에서 조회 | 한 응답의 일관성 확보. 페이지 사이의 쓰기는 다음 응답에 반영되므로 전체 탐색이 고정 snapshot은 아님 |
| 기존 예정일 API·schema·인덱스 유지 | 새 GET /todos/history와 공용 DTO 추가. 합성 6천 행 계획에서 기존 사용자/예정일 인덱스 사용 확인. 운영 규모의 성능·인덱스 결정은 별도 |

계약과 실제 검사 결과: [기록 API](android-v1/history-api.md) · [M-04 보고서](android-v1/implementation-m04.md). 이번 범위에 운영 배포와 Android 기록 화면은 포함하지 않는다.

## 구현 선택 E-002 · 선택적 게시 · 2026-10-23 UTC

후속 개발 진행 지시에 따라 A-06/M-07에서 적용한 호환성 기준이다. P-03~04의 사용자 확정이나 새 운영 정책 승인과 구분한다.

| 선택 | 이유·영향·재검토 조건 |
| --- | --- |
| 게시 기본 PUBLIC, 개인 TODO 기본 PRIVATE 유지 | 기존 API/Web/Android 호환. 시트에서 공개 범위와 원본 공개 범위의 분리를 설명. 기본값 변경은 제품 정책 검토 때 별도 결정 |
| 완료와 게시 별도, 닫아도 완료 유지 | 기존 share=false·서버 게시 계약 재사용. 활성 게시 연결의 완료 취소 제한·snapshot/파기 정책 유지 |
| 그룹은 비어 있지 않으면 기존대로 게시 가능 | 단일 TODO의 완료 조건을 그룹 전체로 확대해 호환성을 바꾸지 않음 |

| 계정·대상·모드별 초안과 사진/제출 상태 복원 | 소유 범위 불일치 시 이전 상태 거부. 실제 OS 기기 복원·사진/DB 전체 통합과 Saver 통과를 구분 |

## 구현 선택 E-003 · 응원·가져오기 · 2026-10-23 UTC

사용자의 후속 진행 지시에 따라 A-07/M-08에서 적용한 개발 선택이다. P-05의 새 제품/보유/복제 정책 승인과 구분한다.

| 선택 | 근거·영향 |
| --- | --- |
| 기존 응원 toggle API·멱등 계약 유지, 앱 범위의 계정/세션/게시물 요청 공유 | 목록·상세가 새 키로 중복 반전하지 않게 함. 실패 원복/같은 키의 명시 확인·성공 후 새 키 |
| 현재 응원 상태 GET과 이전 요청 결과 확인을 구분 | 조회만으로 불확실 키를 지우지 않음. 5분/역행 후 재전송 차단. 만료된 미확인 작업의 서버 처리 조회/원하는 상태 설정은 후속 계약 필요 |
| 기존 clone의 현재 원본·출처·PRIVATE 생성 유지 | 게시 snapshot과 현재 원본이 다를 수 있음을 안내. 원본 수정/비공개/삭제 뒤 권한·기존 복제본 파기 정책은 임의 변경하지 않음 |

| 루틴의 계정별 초안/제출 복원·새 그룹의 소유권 확인 | 불확실 전송/409는 같은 본문/키 확인, 거부401/403/404 잠금. UI·모의 HTTP 통과를 실 DB 권한 경합/OS 복원으로 확대하지 않음 |

## 구현 선택 E-004 · 공개 서버 인가·쓰기 경계 · 2026-10-24 UTC

사용자의 A-08 후속 진행 지시에 따라 실제 HTTP/DB에서 확인한 권한 검사 시점 문제를 수정했다. 새 공개 기본값·원본/복제본 보유 정책·사용자 확정을 추가하지 않는다.

| 선택 | 근거·범위 |
| --- | --- |
| 원본 복제·응원/댓글의 인가와 쓰기를 같은 Serializable snapshot으로 처리 | 사전 조회 뒤 철회된 원본 복제와 숨긴 게시물 상호작용을 실제 재현. source 가시성·작성자 활성·차단 helper도 같은 client 사용 |
| 단일 복제의 분류·대상 그룹 소유권/연결도 같은 트랜잭션에서 처리 | 일부 연결만 반영되거나 외부 사전 조회에 의존하지 않게 함. 공개 요청/응답 계약은 유지 |
| 거부된 쓰기는 보상/알림 없이 종료, 허용된 쓰기의 후속 처리는 기존 계약 유지 | 자동 쓰기 반복을 추가하지 않음. 모든 동시 스케줄/후속 부작용의 원자성을 주장하지 않음 |
| 원본/게시 snapshot/다른 사용자의 복제본/탈퇴 파기를 구분 | 기존 정책과 FK·DB trigger·worker를 실제 검증. 새 보유/파기 기간이나 범위를 임의 도입하지 않음 |

[M-09 확인된 문제·재현·실행 범위](android-v1/implementation-m09.md). 보안 스킬의 참조 세부 파일은 제공되지 않아 해당 가이드 준수 완료로 표시하지 않으며, 전체 운영 보안/기기/출시 검수 완료와 구분한다.
