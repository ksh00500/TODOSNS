## 변경 절차

결정마다 일시·근거·영향 받는 요구/계약·재검토 조건을 기록한다. 제안을 사용자의 승인으로 표현하지 않는다. 과거 handoff 본문을 새 결정으로 덮어쓰지 않는다. 새 설계가 현행 AGENTS·디자인·개인정보 정책과 충돌하면 충돌과 변경 범위를 먼저 명시한다.

## V1 상세 설계 근거 · 2026-10-23

[Android V1](android-v1/README.md)에 화면·상태·API·검수 초안을 추가했다. 현행 완료 취소의 게시 연결 제한과 날짜/관계 보존을 유지하는 방향이며, 실제 완료일 기록은 추가 API 설계안이다. 사용자 승인·구현·실행 검증과 구분한다.

## 구현 선택 E-001 · 완료 기록 API · 2026-10-23 UTC

사용자의 후속 개발 진행 지시에 따라 M-04에 적용한 개발 기준이다. 별도의 사용자 확정 발언이나 운영 정책 승인으로 표현하지 않으며, 제품 검토 때 조정할 수 있다.

| 선택 | 이유·영향·재검토 조건 |
| --- | --- |
| 현재 완료 상태인 본인·미삭제 항목만 completedAt으로 조회 | 기존 TODO·권한·파기 정책 보존. 감사 이벤트 원장·삭제 원문 보관을 추가하지 않음 |
| 기본 최근 7개 현지 날짜, 최대 90일, 기본 20/최대 50개 | 기존 상세 초안의 제한을 개발 기본값으로 적용. 실제 사용성·운영 규모에 따라 조정 |
| 날짜 쌍 생략은 첫 페이지에만 허용 | 이후 페이지는 응답의 fromDate/toDate를 명시해 자정 후 기간이 이동하지 않게 함 |
| 서명 커서를 사용자·기간·canonical timezone·limit·필터 버전에 연결 | 위변조와 다른 조건 재사용 거부. 키 회전/조건 변경은 첫 페이지 재조회 |
| 목록·total·시간대를 RepeatableRead transaction에서 조회 | 한 응답의 일관성 확보. 페이지 사이의 쓰기는 다음 응답에 반영되므로 전체 탐색이 고정 snapshot은 아님 |
| 기존 예정일 API·schema·인덱스 유지 | 새 GET /todos/history와 공용 DTO 추가. 합성 6천 행 계획에서 기존 사용자/예정일 인덱스 사용 확인. 운영 규모의 성능·인덱스 결정은 별도 |

계약과 실제 검사 결과: [기록 API](android-v1/history-api.md) · [M-04 보고서](android-v1/implementation-m04.md). 이번 범위에 운영 배포와 Android 기록 화면은 포함하지 않는다.
