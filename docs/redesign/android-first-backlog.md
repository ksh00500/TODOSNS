# Android 우선 설계 백로그

2026-10-23 (Asia/Seoul) · Android 우선은 사용자 확정, 아래 기능·정책 상세는 설계 후보다.

## 1. 첫 사용부터 가져오기까지

| 단계 | 사용자 행동 | 앱의 책임 | 서버·권한 | 검증할 예외 |
| --- | --- | --- | --- | --- |
| 시작 | 로그인 후 오늘 할 일을 본다 | 세션 상태·빈 화면·재시도와 첫 행동 제공 | 본인 기록만 반환 | 세션 만료, 오프라인, 느린 조회 |
| 생성 | 제목·일정을 입력하고 저장한다 | 폼과 사진 등 초안 소유권·중복 제출 제어 | DTO·소유권·날짜/시간대 확인 | 저장 실패, 화면 재생성, 날짜 경계 |
| 완료 | 할 일을 완료한다 | 완료 피드백, 중복 탭 방지, 실패 원복 | 멱등·완료/취소 상태 일관성 | 늦은 응답, 재시도, 연속 완료·취소 |
| 기록 | 완료 내역을 확인한다 | 날짜/기간 맥락과 조회 오류 구분 | 사용자별 기록 | 비어 있음과 조회 실패 구분 |
| 게시 | 완료 항목을 선택하고 내용을 확인한다 | 게시와 외부 공유 구분, 공개 범위·미디어 상태 안내 | 원본 접근·snapshot·미디어 권한 | 업로드 중, 원본 권한 철회, 완료 취소 |
| 탐색·응원 | 타인 게시물을 보고 응원한다 | 목록 위치 보존·상태 복구 | 공개·차단·탈퇴 경계, 중복 처리 | 더 보기 실패, 차단 후 늦은 응답 |
| 가져오기 | 내 일정으로 조정하고 저장한다 | 원본 미리보기·출처·일정 조정·저장 결과 | 가져오기 허용·새 소유권·원본 경계 | 비공개/삭제 원본, 반복 방식 차이 |
| 재완료 | 가져온 실천을 수행한다 | 개인 목록과 기록에 연결 | 내 TODO 완료 계약 재사용 | 원본 수정과 내 항목 수정의 구분 |

## 2. 기존 코드의 재사용 후보

| 영역 | 현재 코드 | 준비·검토 내용 |
| --- | --- | --- |
| 앱 진입·화면 | `apps/android/app/src/main/java/kr/kro/mungsil/MainActivity.kt`, `ui/TodosScreen.kt` | 현재 내비게이션·화면 상태를 조사하고 새 흐름과 연결 |
| TODO 상태 | `ui/TodoModel.kt` | 불변 StateFlow, 늦은 응답 차단·실패 복구·요청 키 유지 검토 |
| TODO 계약 | `data/TodoRepository.kt`, `data/TodoDraft.kt`, `ui/GroupForm.kt` | 날짜 범위·시간대·완료/취소·수정 의미 보존 |
| 게시 초안 | `data/PublishDraft.kt`, `ui/PublishSheet.kt`, `ui/PhotoDraft.kt` | 초안/미디어 복원·중복 제출·업로드 재사용 검토 |
| 세션 | `data/SecureSessionStore.kt`, `data/GoogleSignIn.kt`, `ui/GoogleLoginModel.kt` | 자체 세션·안전한 저장·provider 실패 상태 유지 |
| API | `apps/api/src/controllers.ts`, `mungsil.service.ts`, `auth.ts`, `media.service.ts` | 기존 권한·트랜잭션·파기 경계와 계약 호환성 조사 |
| 공유 자산 | `packages/contracts`, `packages/content`, `packages/test-fixtures` | 웹/Android의 계약·약관·합성 비교 데이터 재사용 |

경로에 코드가 있다는 사실은 재설계 요구 충족 판정이 아니다. 검토 결과는 유지·개선·대체와 이유로 기록한다.

## 4. 기능별 검증 기준

| 범위 | 필요한 증거 | 대체할 수 없는 항목 |
| --- | --- | --- |
| 모델·Repository | 단위 시험, 합성 HTTP의 지연·오류·중복·권한 응답 | 실 DB 권한·동시성·스토리지 |
| Compose 화면 | 실제 연결 UI 시험, 글자/터치/키보드·초안 복원 | unit 통과만으로 화면·프로세스 종료 통과 판정 |
| 통합 | 실제 합성 DB/스토리지, 두 계정·차단·재시도·소켓 복구 | 문자열 정적 검사·모의 응답 |
| 계정·푸시 | 합성 provider와 실계정/기기 전달을 별도 기록 | 선택 창 표시·FCM validate_only를 실제 성공으로 표현 |
| 배포·릴리스 | 정확한 SHA·서명 산출물·대상별 검증 | Debug 성공으로 Play 배포 완료 판정 |

현재 화면·API 설계 조사는 `887fdef`의 정적 코드 기준이다. [M-01](android-v1/implementation-m01.md)·[M-02 구현·검증 결과](android-v1/implementation-m02.md)는 후속 코드 결과이며, 나머지 M-03~06과 실제 DB/연결 UI 시나리오는 별도다. A-01의 정책 합의 완료를 의미하지 않는다.
