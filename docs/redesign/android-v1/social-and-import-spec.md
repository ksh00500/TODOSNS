# Android V1 · 응원과 내 TODO로 가져오기

2026-10-23 UTC · A-07 / M-08 · F-10/12. 현행 서버 정책을 보존한 개발 설계이며 P-05의 새 제품 정책을 확정하지 않는다.

2026-10-24 후속: [M-10](implementation-m10.md)이 `POST /feed/posts/:id/cheer/result`의 현재 상태 정리·이전 키 차단을 추가했다. 아래 만료 요청의 후속 계약 대기 표현은 M-08 당시 이력이다. 단순 GET만으로 잠금을 풀지 않는 원칙은 유지하며 기기 결과는 [M-11](implementation-m11.md), 전체 현황은 [M-13](implementation-m13.md)을 따른다.

## 1. 사용자 흐름과 계약

| 단계 | 화면·행동 | 서버/소유권 경계 |
| --- | --- | --- |
| 탐색 | 기존5탭과 피드의 `나도 할래요` 주 행동 유지 | 공개 피드·로그인 전환·현재 서버의 차단/가시성 계약 재사용 |
| 응원 | 상태·개수·응원/취소를 함께 표시 | 기존 `POST /feed/posts/:id/cheer`는 현재 상태를 반전하는 toggle. 재시도에 새 키를 만들면 중복 반전할 수 있음 |
| 목록→상세 | 같은 게시물의 응원 결과를 이어 확인 | 앱 범위의 계정/세션별 CheerStore에서 하나의 요청을 공유. 화면 이동·별도 시트가 경쟁 POST를 만들지 않음 |
| 단일 가져오기 | 원본 실천 제목과 새 TODO임을 안내, 일정·분류·반복·공개 범위 확인 | M-02의 계정/대상/clone별 TodoFormState 재사용. 기본 PRIVATE, 원본 수정 없음. 기존 clone API가 새 사용자 소유권과 sourceTodoId를 연결 |
| 루틴 가져오기 | 원본 제목과 내 그룹 이름·시작일/시간·반복 정책 확인 | 기존 `POST /todo-lists/:id/clone`. 서버는 새 PRIVATE 그룹/항목과 sourceTodoListId/sourceTodoId를 생성 |
| 원본 유지/반복 없음 | 원본 항목 간 간격을 유지하거나 반복만 제거 | KEEP/NONE에는 개별 items를 보내지 않음. 서버의 현재 원본 간격/반복 처리 유지 |
| 항목별 설정 | 제목·일정·반복 개별 편집, 모드 전환에도 편집 내용 유지 | CUSTOM만 sourceTodoId별 overrides. 원본으로 초기화는 명시적으로 누를 때만 수행 |
| 권한 변경·삭제 | 서버 거부 사유를 표시, 완료/성공으로 처리하지 않음 | 현재 원본의 읽기 권한·차단·삭제 조건은 서버가 최종 판단. 게시물 가시성과 원본 TODO/그룹의 직접 읽기 권한은 별개일 수 있음 |
| 성공 | 응원은 boolean 응답, 루틴은 새 그룹 ID·현재 계정 소유·PRIVATE 확인 | 잘못된 HTTP 성공 응답은 불확실 상태. 원본과 같은 ID나 다른 소유자의 그룹을 성공 처리하지 않음 |

원본 게시 snapshot과 clone 시점의 현재 원본은 동일하다고 보장하지 않는다. 화면에서 현재 서버 내용을 기준으로 가져온다고 안내한다. 원본이 수정/삭제/비공개가 된 경우의 현재 서버 권한·파기·기존 복제본 처리는 유지하며 신규 영구 복제/출처 삭제 정책을 도입하지 않는다. 서버의 동시 권한 변경 경합과 실 DB 전체 흐름은 별도 A-08 검수 범위다.

## 2. 응원 상태

| 상태 | 표시·허용 행동 | 보존 |
| --- | --- | --- |
| 최초/확인됨 | 응원 또는 취소, 마지막 확인 개수 | 성공 응답의 boolean으로 정규화. API가 전체 개수를 반환하지 않아 개수는 마지막 조회값과 내 변화량으로 계산하며 실시간 전체 개수 보장은 아님 |
| 전송 중 | 낙관적 표시·개수, 추가 전송 잠금 | 이전 상태/개수·키·본문·시각·attempt. 앱 내 목록/상세에서 공유 |
| 실패/전송 취소 | 이전 상태/개수로 원복하고 오류·결과 확인 표시 | timeout/5xx/409/취소는 같은 키로만 명시 확인. 자동 전송 없음 |
| 화면/Compose 복원 | 진행 중이었던 요청도 불확실 상태부터 시작 | 미확인/실패 요청만 저장. 게시 본문·사진·토큰·쿠키는 CheerStore에 넣지 않음. 다른 계정 복원 거부 |
| 현재 응원 상태 조회 | GET으로 현재 boolean/전체 개수만 다시 확인 | 새 POST를 보내지 않음. 불확실 요청의 완료 증명이 아니므로 해당 키/요청은 유지. 확정된 거부 이후 권한 회복의 성공한 읽기는 새 행동의 기준으로 사용 가능 |
| 5분 경과·시계 역행 | 같은 키의 재전송도 차단하고 현재 상태 조회 안내 | 서버 미완료 키 수명을 넘겨 과거 toggle을 다시 실행하지 않음. 새 키 자동 생성·조회만으로 미확인 요청 해제 없음 |

**남은 운영 범위:** 보존 시간이 지난 불확실 응원은 현재 상태를 읽을 수 있어도 이 앱의 해당 요청 상태에서 새 toggle을 계속 차단한다. 현재 API에는 이전 작업의 최종 처리 여부를 조회하는 계약이 없어 자동 해제를 구현하지 않았다. 작업 상태 조회 또는 원하는 상태를 명시하는 서버 계약이 후속 후보이며, 화면 재시작으로 해결됐다고 보고하지 않는다. 같은 요청의 캐시된 성공과 다른 기기에서 변경된 최신 상태도 구분한다.

## 3. 루틴 초안·결과 확인

| 상황 | 동작 |
| --- | --- |
| 작성/복원 | 계정·원본 ID에 연결된 원본 항목의 최소 필드, 기준 초안·현재 초안·시간대와 제출 본문/키/시각을 함께 보존. 원본 전체 JSON/인증값 저장 없음 |
| 모드 전환 | CUSTOM 편집을 KEEP/NONE 전환으로 덮어쓰지 않음. 기존 원본 raw 반복 규칙 보존 |
| 잘못된 이름·빈 그룹·일정 | 입력 오류로 표시하고 전송하지 않음 |
| 전송 중 | 입력·닫기 잠금, 중복 탭 방지 |
| 불확실한 실패/409/복원 | 입력 잠금과 같은 본문/키의 가져오기 결과 확인. 초안 수정으로 새 복제 요청을 자동 생성하지 않음 |
| 5분 경과/시계 역행 | 재전송 차단, 닫은 뒤 TODO 그룹/일정 확인 안내 |
| 확인된400 등 거부 | 내용 유지, 수정 허용. 같은 내용 재시도는 같은 키, 수정한 제출은 새 키 |
| 401/403/404 | 잠금과 사유 표시. 원본/로그인 상태를 확인한 뒤 다시 열기 |
| 닫기 | 미저장/불확실 상태 확인. 이미 저장됐을 수 있고 닫아도 취소되지 않음을 안내. 원본 변경·복제본 자동 삭제 요청 없음 |
