## 이번에 확인한 설계 경계

| 구분 | 코드에서 확인한 사실 | 설계 반영 |
| --- | --- | --- |
| 예정일과 완료일 | GET /todos는 dueDate로 필터링 | completedAt 기준 기록은 별도 계약 초안으로 분리 |
| 완료 취소 제한 | 활성 게시 연결이 있으면 서버가 400 거부 | 완료 상태 원복·사유 안내, 게시물 자동 삭제 없음 |
| 성공 시각 | 완료 API는 todo를 반환하지만 Android Repository는 응답을 버리고 모델이 단말 시각 사용 | 서버 응답 정규화가 첫 구현 후보 M-01 |
| 초안 보존 | 그룹·반복 scope dirty 감지가 이미 존재 | 기존 보호 유지. 누락된 기능으로 오인해 재작성하지 않음 |

기록의 실제 완료일 기준·기본 기간·페이지 크기 등은 설계 제안입니다. 전체 설계의 구현·기기 검증 완료로 해석하지 않습니다. M-01 완료/취소, M-02 폼·제출 복원, M-03 오늘 화면은 후속 구현했고 위 보고서에 실행 범위를 기록합니다. 다음 작업 후보는 **M-04 실제 완료일 기록 API의 정책·계약 구체화**입니다.
