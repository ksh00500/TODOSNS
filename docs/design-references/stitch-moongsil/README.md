## 빠른 평가

### 그대로 참고할 부분

- `탐색`에서 사진과 연결 TODO를 한 카드 안에서 이해시키는 구조
- `나도 할래요`를 응원·댓글보다 강한 행동으로 배치한 우선순위
- `TODO 가져오기`를 별도 집중 화면으로 두고 저장 전에 내용을 수정하게 한 흐름
- `오늘`의 완료·진행 중·예정 상태를 서로 다르게 표현한 카드 구조
- `마이`의 프로필 → 활동 수치 → 등급 → 배지 순서

### 제품 요구사항에 맞게 다시 판단할 부분

- 한글과 영어가 화면마다 섞여 있다.
- `오늘` 화면의 진행률 영역이 커서 실제 TODO가 첫 화면 아래로 밀린다.
- `마이`의 `Pet Profiles`는 현재 뭉실 요구사항에 없는 기능이다.
- 등급이 `Level`, `XP` 중심으로 표현되어 있어 뭉실 고유 등급 명칭과 활동 지표로 변경해야 한다.
- `탐색` 피드에는 TODO 리스트인지 단일 TODO인지 구분하는 정보가 부족하다.
- 공유, 댓글 상세, 복제 수, 챌린지 추천 등 실제 제품 데이터가 일부 빠져 있다.
- 색 대비, 긴 한글 텍스트, 360px 화면, 키보드 조작은 별도 검증이 필요하다.

## 누락된 화면

이번 Stitch 결과물에는 아래 화면이 포함되지 않았다.

- 랜딩
- 로그인, 회원가입, 온보딩
- TODO 주간·월간 캘린더
- 일반 TODO 작성·편집
- TODO 리스트 만들기
- 완료 후 공유
- 게시물 상세·댓글
- 알림
- 챌린지 목록·상세·인증
- 공개 사용자 프로필
- 설정
- 로딩, 빈 상태, 오류, 오프라인, 권한 없음 상태

## 코드 사용 주의

내보낸 `code.html`은 구조를 읽기 위한 정적 샘플이다.

- Tailwind CDN을 사용한다.
- Google Fonts와 Material Symbols를 외부에서 불러온다.
- 피드 이미지와 프로필 이미지가 외부 `googleusercontent.com` URL에 의존한다.
- 버튼과 내비게이션은 실제 데이터·라우팅·상태 관리에 연결되어 있지 않다.
- 외부 이미지의 장기 사용 가능 여부와 라이선스가 확정되지 않았다.

따라서 HTML을 `apps/web`에 복사하지 않는다. 채택할 화면 구조를 먼저 확정한 뒤 현재 Next.js 컴포넌트와 API 계약 위에서 다시 구현한다. 아이콘은 기존 Lucide 체계를 유지하고, 이미지 에셋은 사용 권한이 명확한 파일로 교체한다.

## 다음 적용 순서

1. 네 화면에서 채택할 구조와 버릴 구조를 확정한다.
2. 공통 내비게이션, 헤더, 카드, 버튼의 화면별 불일치를 정리한다.
3. 디자인 토큰을 현재 CSS와 분리된 초안으로 만든다.
4. `오늘 → 완료 → 공유 → 탐색 → 가져오기` 흐름부터 새 디자인으로 교체한다.
5. 360px·390px·430px에서 검증한 뒤 나머지 화면으로 확장한다.
