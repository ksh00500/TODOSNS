# 백엔드 서비스 책임 경계

2026-09-16 현재의 호출 관계와 단계적 분리 기준이다. 공개 HTTP 경로와 응답 계약은 컨트롤러에 유지하고, 서비스 이동 때문에 권한 검사나 트랜잭션 경계가 달라지지 않게 한다.

## 현재 분리된 책임

- `DirectChatService`: 1:1 요청·수락, 멤버십, 전송·답장·반응·삭제, 읽음 위치와 차단 재검사를 소유한다. 차단 뒤에는 기록을 보존하고 메시지 변경만 거부한다.
- `ChallengeChatService`: 챌린지 멤버십과 종료·탈퇴·채팅 제한을 모든 메시지 변경 경로에서 재검사한다.
- `TodoCategoryService`: 카테고리 기본값, 생성·수정·정렬, 카테고리별 TODO 커서 조회를 소유한다.
- `RecurrenceService`: 반복 TODO 발생과 시리즈 계산을 소유한다.
- `MediaService`, `DataGovernanceService`, `MaintenanceService`: 각각 저장소 미디어, 개인정보 수명주기, 운영 유지보수를 소유한다.

`MungsilService`에는 아직 TODO·그룹, 피드·댓글, 챌린지 본문과 운영 조회가 함께 남아 있다. 사용되지 않던 이전 1:1 메시지 구현은 제거했고, 신고 흐름에서 사용하는 멤버십 보조 검사만 유지한다.

## 다음 분리 단위와 보존 조건

1. TODO와 그룹: TODO 소유권, 반복 시리즈의 단일 그룹 소속, 그룹 구성 변경 트랜잭션을 한 경계로 둔다. 선택 날짜 조회는 고정 `take` 없이 전체를 반환한다.
2. 피드와 댓글: 게시 원본 접근권한, 차단 사용자 제외, 응원·댓글의 낙관적 갱신 보상, `(createdAt, id)` 커서를 함께 이동한다.
3. 챌린지 본문: 참여·탈퇴·종료와 인증 판정의 권한 및 중복 요청 방지를 한 경계로 둔다. 채팅 변경은 `ChallengeChatService`에 유지한다.
4. 운영 기능: 관리자 역할 검사는 컨트롤러 표시가 아니라 서비스 진입점에서 유지하고, 향후 MFA 재인증은 공통 가드로 적용한다.

각 분리는 컨트롤러 경로, `packages/contracts`, 트랜잭션 범위와 오류 코드를 먼저 고정한 뒤 한 도메인씩 진행한다. 공통 권한 로직을 복사한 병렬 서비스는 만들지 않는다.
